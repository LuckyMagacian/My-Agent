# 版本迭代组件（version-evolution）

> 版本：v1.1
> 文档属性：skill 交付文件（原子组件——版本演进治理）
> 定位：skill 版本演进事务的唯一权威规范与记录组件——承载版本总账、规约 changelog 用法、定义升版与引用侧同步纪律；组件本体机制冲突时不适用本文，以各组件原文为准
> 对齐基准：SKILL.md v1.0.16、work-mode v1.9、context-system v2.3.7、requirements-stage v0.8.10、design-stage v0.9.5、development-stage v1.3、testing-stage v1.4
> 关键约定：本文只治理版本演进事务（版本号、升版、记录、同步义务），不定义、不复述任何流程机制，机制冲突一律以组件原文为准（冲突规则见 SKILL.md §2）；总账与 changelog 明细不双写（分工与冲突口径见 §1、§5.2）
> 版本演进留痕：本文即版本演进记录的权威文档；迁移完成后各组件头部留痕指针行指向本文（模板见 §3.4）；本文自身的版本变更见 §4

## 1. 定位与关系

本文与既有组件/载体的分工：

| 对象 | 关系与分工 |
| --- | --- |
| changelog/ 目录 | 版本变更**明细档案**，按日归档（用法规约见 §3），是全部版本细节的唯一权威；本文 §4 总账为轻量指针表，不双写 |
| SKILL.md §2 组件登记表 | 组件当前版本与职责的**现行快照**；版本历史由本文 §4 与 changelog 承载，登记行只记现行状态 |
| 上下文体系 §4 目录布局 / §12 关系 | 文件清单与组件关系的现行快照；版本历史不在此承载 |
| 交叉引用索引（references/cross-reference-index.md） | 引用正确性校验工具；本文升版时的引用侧同步受其「末次校验」与分组行约束（§2.4） |
| 执行检查清单（references/execution-checklist.md） | 执行导航工具，无版本号；其建立事件已记入 §4 总账 |
| 各组件文档头部 | 头部只承载当前版本、对齐基准、指向本文的留痕指针（§3.4），历史注释不再保留于头部 |

## 2. 版本号与升版规约

### 2.1 版本号语义

| 段位 | 语义 |
| --- | --- |
| v0.x | 评估迭代期版本（work-mode 双视角评估中逐轮修订；组件可于该阶段收敛定稿） |
| v1.0 | 首个正式发布版本 |
| Y / Z 增量 | 机制增量或结构调整 → Y 增；修订、澄清、元数据同步 → Z 增。历史存在机制修订走 Z 位的先例，后续升版以本行为准 |

### 2.2 升版触发

| 变更性质 | 处置 |
| --- | --- |
| 常规机制增量（新增/修改条款、结构调整） | 直接补丁流程升版，同批完成 §2.4 引用侧同步 |
| 纯元数据同步（含新增登记行、布局树新增行） | 不升机制版本，同批完成 §2.4 引用侧同步相关项与 changelog 条目；**SKILL.md 例外，每次变更均升号** |

### 2.3 记录粒度

总账一行一组件/事件；指针按日登记（changelog/<日期>.md），当日批次为最小登记单位，不枚举条目号、不复述细节；历史版本细节以 changelog 明细为唯一权威。

### 2.4 引用侧同步义务

升版定稿时**同批**完成以下七处引用侧同步；其中第 2、3 项对新组件为「新增行」，对其余为「更新行」。**遗漏任一项即视为修订未完成**：

1. 引用方组件头部「对齐基准」行；
2. SKILL.md §2 登记表对应行的版本列（新组件为新增登记行）；
3. 《上下文体系》§4 目录布局树中的文件行（新组件为新增行）；
4. 《上下文体系》§12 关系表版本行（含 SKILL.md 升号时的反向同步行）；
5. 交叉引用索引「末次校验」行（无条件；本批存在《别名》§章节形式的新增或变更出向引用时，对应索引分组行同批登记）；
6. 交叉引用索引中引用本文的分组行（条件：存在《别名》§章节形式的引用时；指针式引用不产生此行）;
7. changelog/ 当日条目（格式见 §3）。

## 3. changelog 用法规约

### 3.1 命名与归属

| 规则 | 内容 |
| --- | --- |
| 文件命名 | `changelog/<YYYY-MM-DD>.md`，一日一文件；假定单次变更不跨日 |
| 内容归属 | 承载机制变更、迁移、工具文件建立等**事件级明细**；不承载运行实例过程记录（过程产物归档见《工作模式》§10.5） |
| 条目粒度 | 一升版一条目；跨版本合并评估定稿允许一条目记多版本 |

### 3.2 条目格式

按批次记录：【迁移】一节一文档；【当日新增】节内以「触发」段分隔批次，各触发段记触发源与决策留痕——采纳范围与拒绝项（含原则性理由）必须记录。条目含：文件 + 版本号（迁移类另记迁出前版本）、一句话摘要、涉及机制要点、指针（组件 §章节）；**仅元数据的同步须显式标注「仅元数据」**。目录/布局类建立事件（如本文建立、检查清单建立）同样记入 changelog，随所在批次性质记录。

### 3.3 迁移条目格式

`【迁移】<文档名>（历史演进，迁出前版本 <版本>）`；正文为零失真迁入的版本演进明细；迁移当日的头部处置（删演进注释、保留当前版本与对齐基准）记入当日条目。

### 3.4 文档头部规则

各组件文档头部只承载三项：现行版本与对齐基准（各文档既有格式不变）、留痕指针行。指针行为固定模板：

`> 版本演进留痕：本文版本演进注释已迁移至 skill 的版本迭代组件（references/version-evolution.md，含总账与 changelog 明细指针），头部仅保留当前版本与对齐基准`

迁移完成后各组件头部留痕指针行统一指向本文；指针的修改属纯元数据同步（§2.2），留痕入 changelog 当日条目。

## 5. 治理流程

### 5.1 修订流程选择口径

| 情形 | 流程 |
| --- | --- |
| 常规升版（机制增量、修订、元数据同步） | 直接补丁，同批完成 §2.4 引用侧同步与 changelog 条目 |
| 重大新组件或机制族群 | work-mode 实例评估，经执行者—评估者—仲裁者双视角评估定稿 |

### 5.2 记录与留痕纪律

1. 本文头部版本演进留痕行为本文自身的版本记录指针；
2. work-mode 实例评估的过程产物按《工作模式》§10.5 归档，不随组件文档承载；
3. 总账与 changelog 明细不双写：总账行只记指针，机制细节以 changelog 明细为唯一权威；发现不一致时，版本存在性以总账为准、细节以明细为准，并修订另一方对齐；
4. **登记一致性义务**：组件头部现行版本、SKILL.md §2 登记行、《上下文体系》§12 版本行三处须保持一致，由升版批次同批完成（§2.4），不一致时按上述第 3 项口径对齐。
