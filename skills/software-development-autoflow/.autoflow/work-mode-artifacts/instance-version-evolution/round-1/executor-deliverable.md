### 2. 版本规约

#### 2.1 版本号语义

语义化版本三段式 `vX.Y.Z`：

- **v0.x**：评估期草稿版本（work-mode 双视角评估迭代中的修订）；
- **v1.0**：首次收敛定稿交付版本；
- **次版本（Y）增量**：机制增量（新增/修改/删除行为定义）；
- **修订号（Z）增量**：小幅机制修订或整改轮定稿。

#### 2.2 升版触发

| 改动性质 | 处置 |
| --- | --- |
| 机制增量（行为定义新增/修改/删除） | **直接补丁升版**——修订落盘即升版，升版触发条件与修订内容记入 changelog 当日文件 |
| 纯元数据同步（对齐基准行、登记表版本列、留痕指针、§12 关系行） | **不升该文档机制版本**（P2-1 裁定固化：机制正文零改动即不升版） |
| `SKILL.md` 例外 | SKILL.md 版本反映组件体系整体版本集，**每次改动（含引用侧元数据同步）均升号**——既有先例 v1.0.1~v1.0.5 均如此 |

#### 2.3 总账行粒度口径

总账每版本一行摘要 + 明细指针；**行粒度以源明细形态为准、无失真优先**（P2-4 裁定固化）——源明细的合并版本行（如 design-stage v0.2–v0.6）按原合并形态入总账，不强行拆分；摘要为概括性一句话，不复制明细的过程性描述。

#### 2.4 引用侧同步义务

组件升版时，**同批**同步全部引用侧点位（遗漏即视为修订未完成）：

1. 引用方文档头部「对齐基准」行；
2. `SKILL.md` §2 组件登记表版本列；
3. 《上下文体系》§12 登记表对应行（含 SKILL.md 升号时的反向同步行——SKILL.md 登记行版本号）；
4. `references/cross-reference-index.md` 末次校验行版本集（无条件）；被引方分组行新增（仅当新组件被其他组件以《别名》§章节形式引用时）；
5. changelog 当日文件条目。

### 3. changelog 用法

#### 3.1 命名与归属

- 文件名 `<YYYY-MM-DD>.md`，按改动日期命名；假定单次改动不超过一天；
- 一次改动的**全部条目**记入当日文件，不跨文件拆分；
- 多批改动同日的，以「触发（第 N 批）」分段，各批含决策留痕（采纳范围与**拒绝项的原则性理由**）。

#### 3.2 条目格式

- 编号条目：`N. **<文档> vX → vY**：<变更摘要>`；
- 引用侧元数据同步单独成条，标注「仅元数据」；
- 新建文件、迁移类条目标注操作性质（新建 / 迁移 / 登记同步）。

#### 3.3 迁移条目格式

历史演进注释迁入时以 `## 【迁移】<文档>（历史演进，迁出前版本 vX）` 分节，内容零失真搬运；迁移批次与当日新增批次分列。

#### 3.4 文档头部规则

- 文档头部**仅保留**当前版本号与对齐基准；
- 演进注释一律不写入头部，迁入 changelog（历史）与本文总账（摘要）；
- 头部留痕指针行统一表述为指向本文（`references/version-evolution.md`）的固定格式，指针改造属纯元数据同步（§2.2，不升各组件机制版本）。
