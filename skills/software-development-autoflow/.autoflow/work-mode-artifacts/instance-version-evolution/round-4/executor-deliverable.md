## 2. 版本号与升版规约

### 2.1 版本号语义

| 段位 | 语义 |

### 2.2 升版触发

| 变更性质 | 处置 |

总账一行一组件/事件，指针直指明细节，不复述细节；历史版本细节以 changelog 明细为唯一权威。

升版定稿时**同批**完成以下七处引用侧同步；其中第 2、3 项对新组件为「新增行」，对其余为「更新行」。**遗漏任一项即视为修订未完成**：

1. 引用方组件头部「对齐基准」行；
2. SKILL.md §2 登记表对应行的版本列（新组件为新增登记行）；
3. 《上下文体系》§4 目录布局树中的文件行（新组件为新增行）；
4. 《上下文体系》§12 关系表版本行（含 SKILL.md 升号时的反向同步行）；
5. 交叉引用索引「末次校验」行（无条件）；
6. 交叉引用索引中引用本文的分组行（条件：存在《别名》§章节形式的引用时；指针式引用不产生此行）;
7. changelog/ 当日条目（格式见 §3）。

## 3. changelog 用法规约

### 3.1 命名与归属

| 规则 | 内容 |
| --- | --- |
| 文件命名 | `changelog/<YYYY-MM-DD>.md`，一日一文件；假定单次变更不跨日 |
| 内容归属 | 承载机制变更、迁移、工具文件建立等**事件级明细**；不承载运行实例过程记录（过程产物归档见《工作模式》§10.5） |
| 条目粒度 | 一升版一条目；跨版本合并评估定稿允许一条目记多版本 |

### 3.2 条目格式

按批次分节，节头以性质标记（【迁移】/【当日新增】）+ 触发源与决策留痕——采纳范围与拒绝项（含原则性理由）必须记录。条目含：文件 + 版本号（迁移类另记迁出前版本）、一句话摘要、涉及机制要点、指针（组件 §章节）；**仅元数据的同步须显式标注「仅元数据」**。目录/布局类建立事件（如本文建立、检查清单建立）同样记入 changelog，属【新增】性质。

### 3.3 迁移条目格式

`【迁移】<文档名>（历史演进，迁出前版本 <版本>）`；正文为零失真迁入的版本演进明细；迁移当日的头部处置（删演进注释、保留当前版本与对齐基准）记入当日条目。

### 3.4 文档头部规则

各组件文档头部只承载三项：现行版本与对齐基准（各文档既有格式不变）、留痕指针行。指针行为固定模板：

`> 版本演进留痕：本文版本演进注释已迁移至 skill 的版本迭代组件（references/version-evolution.md，含总账与 changelog 明细指针），头部仅保留当前版本与对齐基准`

迁移完成后各组件头部留痕指针行统一指向本文；指针的修改属纯元数据同步（§2.2）。
