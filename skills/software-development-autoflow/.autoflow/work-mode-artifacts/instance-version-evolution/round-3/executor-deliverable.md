## 二、版本号与升版规约

### 2.1 版本号语义

| 段位 | 语义 |
| --- | --- |
| v0.x | 评估迭代期版本（work-mode 双视角评估中逐轮修订；组件可于该阶段收敛定稿） |
| v1.0 | 首个正式发布版本 |
| Y / Z 增量 | 机制增量或结构调整 → Y 增；修订、澄清、元数据同步 → Z 增（沿用《上下文体系》§4 既有惯例） |

### 2.2 升版触发

| 变更性质 | 处置 |
| --- | --- |
| 机制增量（新增/修改条款、结构调整） | 直接补丁流程升版，同批完成 §2.4 引用侧同步 |
| 纯元数据同步（含新增登记行、布局树新增行） | 不升机制版本，仅更新头部基准行；**SKILL.md 例外，每次变更均升号** |

### 2.3 记录粒度

总账每版本一行摘要 + 明细指针；**行粒度以源明细形态为准，无失真优先**：源明细为合并形态的版本行（含后续纯元数据同步），总账按原合并形态记录，不拆分；摘要为一句概述，不复述明细过程性描述。

### 2.4 引用侧同步义务

升版定稿时**同批**完成以下七处引用侧同步；其中第 2、3 项对新组件为「新增行」，对其余为「更新行」：

1. 引用方组件头部「对齐基准」行；
2. SKILL.md §2 登记表对应行的版本列（新组件为新增登记行）；
3. 《上下文体系》§4 目录布局树中的文件行（新组件为新增行）；
4. 《上下文体系》§12 关系表版本行（含 SKILL.md 升号时的反向同步行）；
5. 交叉引用索引「末次校验」行（无条件）；
6. 交叉引用索引中引用本文的分组行（条件：存在《别名》§章节形式的引用时；指针式引用不产生此行）;
7. changelog/ 当日条目（格式见 §3）。

## 三、changelog 用法规约

### 3.1 命名与归属

| 规则 | 内容 |
| --- | --- |
| 文件命名 | `changelog/<YYYY-MM-DD>.md`，一日一文件；假定单次变更不跨日 |
| 内容归属 | 承载机制变更、迁移、工具文件建立等**事件级明细**；不承载运行实例过程记录（过程产物归档见《工作模式》§10.5） |
| 条目粒度 | 一升版一条目；跨版本合并评估定稿允许一条目记多版本 |

### 3.2 条目格式

每条含：文件 + 版本号（迁移类另记原版本→新版本）、变更性质（【新增】/【修订】/【迁移】）、一句话摘要、涉及机制要点、指针（组件 §章节）；头部以批次分节（【迁移】/【当日新增】）。目录/布局类建立事件（如本文建立、检查清单建立）同样记入 changelog，属【新增】性质。

### 3.3 迁移条目格式

`【迁移】<文档名>：原版本→新版本`；正文说明「机制内容零变化」及头部留痕指针行的迁移形态。

### 3.4 文档头部规则

各组件文档头部只承载三项：现行版本与对齐基准（各文档既有格式不变）、留痕指针行。指针行为固定模板：

`> 版本演进留痕：本文版本演进注释已迁移至 skill 的版本迭代组件（references/version-evolution.md，含总账与 changelog 明细指针），头部仅保留当前版本与对齐基准`

迁移完成后各组件头部留痕指针行统一指向本文；指针的修改属纯元数据同步（§2.2）。
