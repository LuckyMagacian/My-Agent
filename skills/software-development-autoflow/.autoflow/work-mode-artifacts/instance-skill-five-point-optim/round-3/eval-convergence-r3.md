### A（建议级）§4.5「测试代码实现归属」升级人工裁定分支：触发判据与裁定选项未定义（J-1 修复后裁定链路仍缺两环）

**位置**：references/testing-stage.md §4.5 第 1 段 L95（J-1 新增）

**原文摘录**："**测试代码实现归属**：优先复用工程既有测试代码直接执行，代码缺失时由 Main Agent 依 §5.2 测试基础约定编写并登记入 §4.4 对应测试代码清单（标注「测试阶段新增」），或升级人工裁定（登记验收核验记录人工裁定段）"

**对照**：同节第 3 段「依赖故障登记」的升级方向均带裁定选项（"基础设施缺陷…升级人工（裁定选项：① 补齐基础设施依赖后可重新进入入口判定；② **终止本阶段**——决策留痕；裁定登记验收核验记录人工裁定段并受 §7.4 强制确认约束）"）；「测试代码实现归属」升级人工分支无触发判据（何种情形判定"不宜由 Main Agent 编写"）、无裁定选项（人工裁定什么：接受缺失？终止？指派外部编写？）。

**期望标准**：裁定分支三要素（触发判据 / 裁定选项 / 留痕与确认约束）与其他升级分支同构（r2 曾以同型缺口裁出重要级 J-1，本处为修复后残留的建议级口径缺口）。

**修改方向**：补触发判据（如测试代码编写超出 Main Agent 能力范围、需人工授权的外部资源/凭据）与裁定选项（如 ① 人工提供或授权测试代码后继续执行；② 终止本阶段——决策留痕），并声明留痕登记与 §7.4 强制确认约束归属。
