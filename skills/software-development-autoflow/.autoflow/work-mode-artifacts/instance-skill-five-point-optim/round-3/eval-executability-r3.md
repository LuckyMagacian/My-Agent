## 4. 逐条问题

### A（建议级）§4.5「测试代码实现归属」升级人工裁定分支：执行者无触发判据与裁定选项指引

**位置**：references/testing-stage.md §4.5 第 1 段 L95（J-1 新增）

**原文摘录**："代码缺失时由 Main Agent 依 §5.2 测试基础约定编写并登记入 §4.4 对应测试代码清单（标注「测试阶段新增」），或升级人工裁定（登记验收核验记录人工裁定段）"

**对照**：同节第 3 段「依赖故障登记」升级分支给出裁定选项（"① 补齐基础设施依赖后可重新进入入口判定；② **终止本阶段**——决策留痕"）；「测试代码实现归属」分支只有"升级人工裁定（登记…）"——执行者（Main Agent）在何种情形下应判定"不宜自编、须升级"无判据（能力边界？授权边界？）；升级后人工裁定什么、有哪些选项无定义，执行者无法预演后续路径。

**期望标准**：E1/E4——异常分支具备与正常路径同等的可操作性：触发条件可判定、裁定选项可枚举、结果路径可预演。

**修改方向**：补触发判据（如测试代码编写超出 Main Agent 能力范围、需人工授权的外部资源/凭据）与裁定选项（如 ① 人工提供或授权测试代码后继续执行；② 终止本阶段——决策留痕），并声明登记与 §7.4 确认约束归属。

### B（建议级）新增「经 §7.2 修复定稿」裸引用：失败 TI 重跑前置条件「处置完成」判定歧义

**位置**：references/testing-stage.md §4.5 第 1 段 L95（J-1 新增）

**原文摘录**："处置完成后（工程实现缺陷经 §7.2 修复定稿并通过构建闸门复验 / 设计用例缺陷经人工裁订正 / 基础设施缺陷补齐）由 Main Agent **重新执行**并回写第 2 段执行记录"

**对照**：本文件 §7.2 无「修复定稿」语义（§7.2 为升级人工出口映射 + 缺陷出口三处置集），「修复定稿」实属开发阶段缺陷修复回退通道（《上下文体系》§8.2）承载；L112 既有表述已带出通道（"按缺陷回退 §7.2 处置（关联任务条目 ID 后经开发阶段缺陷修复回退通道重新激活对应任务实例）"）。执行者按 §4.5 判定"处置完成"时，若按本文件 §7.2 处置集（回退上游/接受/转出）理解，可能将"裁定接受/转出"误判为可触发重跑的前置——与 J-1 修复意图（工程缺陷修复定稿后重跑）不符。

**期望标准**：E1——处置完成的前置条件引用与既有通道表述同构，无指代歧义。

**修改方向**：改为「工程实现缺陷经开发阶段缺陷修复回退通道（《上下文体系》§8.2）修复定稿并通过构建闸门复验」，或与 L112 同构表述。
