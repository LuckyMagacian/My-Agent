## 4. 逐条问题

### A（建议级）§4.5「测试代码实现归属」升级裁定分支缺触发判据与裁定选项——异常场景下执行者行为不确定

**位置**：references/testing-stage.md §4.5 第 1 段 L95（J-1 新增）

**原文摘录**："代码缺失时由 Main Agent 依 §5.2 测试基础约定编写并登记入 §4.4 对应测试代码清单（标注「测试阶段新增」），或升级人工裁定（登记验收核验记录人工裁定段）"

**对照**：同节第 3 段「依赖故障登记」升级分支带裁定选项与确认约束（"升级人工（裁定选项：① 补齐基础设施依赖后可重新进入入口判定；② **终止本阶段**——决策留痕；裁定登记验收核验记录人工裁定段并受 §7.4 强制确认约束）"）；「测试代码实现归属」分支无触发判据（Main Agent 何时应升级而非自编）、无裁定选项（人工裁定后有哪些出口——继续/终止？）、未声明 §7.4 确认约束归属——异常场景（如测试代码需外部凭据/专有设备驱动）下执行者行为不确定。

**期望标准**：R1——所有升级人工分支三要素同构（触发判据 / 裁定选项 / 留痕与确认约束），异常场景下执行路径可穷举。

**修改方向**：补触发判据（超出 Main Agent 能力范围 / 需人工授权资源）与裁定选项（① 人工提供或授权测试代码后继续执行；② 终止本阶段——决策留痕），声明登记验收核验记录人工裁定段并受 §7.4 强制确认约束（或显式豁免并说明）。

### B（建议级）重跑前置「处置完成」含裸引用「经 §7.2 修复定稿」——恢复触发条件判定歧义

**位置**：references/testing-stage.md §4.5 第 1 段 L95（J-1 新增）

**原文摘录**："处置完成后（工程实现缺陷经 §7.2 修复定稿并通过构建闸门复验 / 设计用例缺陷经人工裁订正 / 基础设施缺陷补齐）由 Main Agent **重新执行**并回写第 2 段执行记录"

**对照**：本文件 §7.2 为「升级人工出口映射 + 缺陷出口三处置集」（回退上游/接受/转出/追加约束），无「修复定稿」语义；恢复触发条件中"工程实现缺陷修复定稿"实由开发阶段缺陷修复回退通道（《上下文体系》§8.2）承载（L112 既有表述已带出通道）。裸引用使"处置完成"的可判定性受损——按本文件 §7.2 处置集理解时，"裁定接受/转出"不属于可触发重跑的前置，但文本未排除该误读。

**期望标准**：R1/R2——恢复触发条件引用与既有通道表述同构，异常路径判定无歧义。

**修改方向**：改为「工程实现缺陷经开发阶段缺陷修复回退通道（《上下文体系》§8.2）修复定稿并通过构建闸门复验」，或与 L112 同构表述。
