### 问题 2（重要级，C3）：基础设施缺陷处置路径引用不存在的「工程环境就绪」问询机制

- 位置：`references/testing-stage.md` §4.5 第 3 段·处置路径（L108）与 §5.1.5 升级规则（L185）
- 原文摘录：
  - L108：「基础设施缺陷（数据库 / 测试域名 / mock 不可用）：退回上游「工程环境就绪」问询（升级人工，参照 §5 入口条件升级规则）；」
  - L185：「核验失败的依赖项：登记入 §4.5 第 3 段「依赖故障登记」——按故障类别（数据库 / token / 测试域名 / mock）与升级方向（基础设施缺陷 / 工程实现缺陷 / 设计用例缺陷）处置；基础设施缺陷退回上游「工程环境就绪」问询（升级人工），工程实现缺陷按 §7.2 缺陷回退处置，设计用例缺陷升级人工裁定制；」
- 期望标准：C3 无断环——每类故障的处置路径须可追溯至实际存在且语义明确的上游机制。经全工作区核验（SKILL.md、references/ 全部组件、changelog、optimization-log），「工程环境就绪」仅出现于 testing-stage.md 自身 2 处，上游组件（《开发阶段》§5.1 入口准备、《需求阶段》§5.0、《工作模式》§9.5）均无同名或等义问询机制，基础设施缺陷类故障的处置路径悬空，无法执行。
- 修改方向：二选一——① 在上游组件（开发阶段 §5.1 或工作模式）定义「工程环境就绪」问询并给出「路径+章节号」锚点（既有最接近机制为《开发阶段》§5.1 工作空间工程确认，可显式引用并明确映射语义）；② 删除悬空引用，将基础设施缺陷并入 §5.1.5 升级规则既有路径（问询上限/停滞/不可达 → 升级人工，裁定补齐后续流或终止本阶段，登记验收核验记录人工裁定段）。

### 问题 3（重要级，C1）：test-cases.md「入口必备」缺少 G0 与 §5.1 的可执行核验落点

- 位置：`references/testing-stage.md` §5 入口条件（L156）、§5.1 入口就绪核验（L164-167）；对照 §3 输入②（L42）与流程图 IN 节点（L122）
- 原文摘录：

  - L156：「**入口条件**：开发阶段已定稿（阶段级人工确认通过），且开发出口产物齐备（各任务定稿交付物与摘要、任务清单状态全部「定稿」、构建闸门记录通过结论、阶段定稿摘要）+ 需求定稿产物可引用（验收标准逐条、回归边界（如适用））；不满足时不启动本阶段——由 Main Agent 退回上游补充，达补充上限（默认 **3 次**，可由编排者启动时调整）或上游不可达时升级人工…」
  - L164：「**产物齐备**：开发出口产物按入口条件清单齐备，任务清单状态全部「定稿」（读取落盘文件核验，不凭摘要转述）；」
