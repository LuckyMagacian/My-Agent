## 3. 评估对象与基线

- 被评 10 文件同 r1（工作区未提交改动，`git diff HEAD` 统计：**+395 / -55**）；
- 修复仅涉及 4 个文件（requirements-stage / development-stage / testing-stage / design-stage），其余 6 文件与 r1 一致；
- 各视角评估标准（维度分解、评分锚定、输出五段结构、取材边界）**沿用 round-1/eval-standards-r1.md §2/§3/§4**，不作变更；

## 4. 输出要求（同 r1）

- 按 eval-standards-r1.md §3 五段结构输出（视角 ID 与轮次 / 总评分及维度分解 / 收敛建议及依据 / 逐条问题（级别+位置+原文摘录+期望标准+修改方向）/ 无问题维度标注「通过」）；

- 评分 1–10（一位小数）；评分 ≥ 8 且无阻断级才可「建议收敛」；
- **修复闭合核验小节**：报告末尾单独列出与自身视角相关的 I-1~I-6 条目闭合状态（已闭合 / 未闭合 / 部分闭合 + 理由），并检查修复是否引入新问题。
