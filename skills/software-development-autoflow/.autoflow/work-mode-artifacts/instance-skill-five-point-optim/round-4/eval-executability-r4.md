### 问题 1（建议级，r3 遗留 S3-2）——测试代码实现归属升级裁定分支缺触发判据与裁定选项

- **位置**：`references/testing-stage.md` §4.5 执行归属段（L95）
- **原文摘录**：「…代码缺失时由 Main Agent 依 §5.2 测试基础约定编写并登记入 §4.4 对应测试代码清单（标注「测试阶段新增」），或升级人工裁定（登记验收核验记录人工裁定段）」
- **期望标准**：对比 §4.5 第 3 段依赖故障登记「升级人工（裁定选项：① …；② 终止本阶段）」——升级人工分支应给出触发判据（何时不选择 Main Agent 编写而升级，如跨工程复用权衡、工程量超限、需人工指定实现路径）与裁定选项（① 指定路径后 Main Agent 编写；② 豁免该 TI / 终止本阶段），否则执行者面对「或升级人工」无法判断
- **修改方向**：§4.5 执行归属段补触发判据与裁定选项（与 §7.4 锚点、§4.3 来源枚举同步，见 convergence-r4 问题 1）

### 问题 2（建议级，r2 遗留 S2-4）——§5.1.5 问询上界仅数据库项显式

- **位置**：`references/testing-stage.md` §5.1.5（L181-184）
- **原文摘录**：数据库项「探查无法确定时向用户问询（问询上界与停滞规则比照《开发阶段》§5.1：默认 3 轮，达上限/停滞/不可达升级人工）」；token 项「无可用机制时向用户问询获取方式（直接登录账号 / mock 账号凭据 / 测试环境预置 token——任一即可）」；域名项「无可用配置时向用户问询（测试域名 / 桩服务 / 本地启动回环地址——任一即可）」；mock 项无问询表述；升级规则「问询达上限 / 停滞 / 需求方不可达 → 升级人工」声明统一适用四项

- **修改方向**：§5.1.5 升级规则段显式声明问询上界默认 3 轮（比照《开发阶段》§5.1）统一适用四项，或各项补注
