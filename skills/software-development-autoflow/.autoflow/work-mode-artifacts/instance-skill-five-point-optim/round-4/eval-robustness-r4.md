## 4. 逐条问题

### 问题 1（建议级，r3 遗留 S3-4）——§4.5「工程实现缺陷经 §7.2 修复定稿」裸引用

- **位置**：`references/testing-stage.md` §4.5 执行归属段（L95）
- **原文摘录**：「…执行失败的 TI 按第 3 段「依赖故障登记」升级路径处置，处置完成后（工程实现缺陷经 §7.2 修复定稿并通过构建闸门复验 / 设计用例缺陷经人工裁订正 / 基础设施缺陷补齐）由 Main Agent **重新执行**…」
- **期望标准**：本文件 §7.2 为「升级人工出口在本阶段的映射」（L296），其中缺陷出口三处置集与回退上游映射均无「修复定稿」语义；「修复定稿 + 构建闸门复验」的正确语义在《开发阶段》§7.2（「修复定稿后一律重跑构建闸门」）与本文件 §5.5（「修复定稿且闸门通过后，Main Agent 以缺陷复验为追加约束重启受影响测试实例」）。裸引用应限定为「经《上下文体系》§8.2 缺陷修复回退通道重新激活开发实例，修复定稿（《开发阶段》§7.2）并通过构建闸门复验后」
- **修改方向**：§4.5 执行归属段处置完成后括注限定为《开发阶段》§7.2 修复定稿语义（沿 §4.5 第 3 段「按缺陷回退 §7.2 处置（关联任务条目 ID 后经开发阶段缺陷修复回退通道重新激活对应任务实例）」同口径）
