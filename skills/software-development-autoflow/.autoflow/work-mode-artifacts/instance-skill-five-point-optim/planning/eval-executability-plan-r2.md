**A-1 S4 基线比对「排除 .autoflow/」与「限定 10 文件」自相矛盾，判据不可机械执行**
- 位置：plan-r2.md §5 风险表「组件文件被误修改」行（L48）；变更说明 S-5（L71）
- 摘录："S4 复跑基线快照命令（`git status --porcelain` + `git diff HEAD -- <10 文件>`）与 S1 基线比对，比对范围限定 10 文件、排除 `.autoflow/`"
- 问题：评估对象 #10（`.autoflow/optimization-log/2026-08-11-skill-five-point-optimization.md`）为已跟踪、已修改文件（git status 实测为 M），本身位于 `.autoflow/` 下。按字面执行将把 #10 移出「评估仅留痕」守卫闸口（该文件恰是本次被评组件之一）；另一解释（排除项仅针对 `?? .autoflow/work-mode-artifacts/` 评估留痕目录）则与「排除 .autoflow/」字面不符。执行者必须临场消歧，S4 完成判据不可机械执行——本判据恰为闭合 plan-P-10「核验口径不可执行」所设，缺陷同型复现。
- 改进：排除范围精确为 `.autoflow/work-mode-artifacts/`（评估留痕目录），并显式声明 #10 优化日志保留在比对范围内；如成本允许，给出具体命令示例（如 `git diff HEAD -- <10 文件显式路径>` 逐文件比对 + `git status --porcelain` 过滤 work-mode-artifacts 行）。

**A-2 plan-P-8 部分闭合：round-N/ 落盘结构仍未显式**
- 位置：plan-r2.md S2（L24）、S3（L25）、S4（L26）；变更说明 S-3（L69）
- 摘录：S3 ① "（executor-deliverable.md，§10.4 五段结构，含变更说明/摘要/未落实项）"；S4 "核验全部产物落盘（五份视角报告 + 仲裁记录 + 定稿整合报告 + issue-log + 实例终态补记）"
- 问题：全计划未出现 round-N/ 目录，而实例范围（instance-context.md）显式声明交付物为「round-N/executor-deliverable.md」；S2 硬编码 eval-<视角ID>-r1.md，后续轮次命名仅可依 §10.5 推断。实际后果：计划自身定义的第 2 轮再入时，executor-deliverable.md 若落实例根目录将覆盖首轮草稿（整合报告无轮次后缀，轮次仅靠 round-N/ 目录承载）。S-3 将原问题（落盘结构未显式）收窄为「枚举五类产物」，属部分承接。连带问题：S1 基线快照落盘 planning/baseline-r1.txt 属执行阶段产物，与 §10.5 归档结构（planning/ 仅规划阶段文件）错位，且 -r1 后缀与规划轮次（plan-r2）易混。
- 改进：按 §10.5 在 S2/S3/S4 显式标注落盘目录：首轮 `round-1/`（executor-deliverable.md、eval-<视角ID>-r1.md、arbitration-r1.md、baseline.txt），第 2 轮起 `round-2/` 等；S2 产出命名改为 eval-<视角ID>-r<N>（N = 执行轮次）；S1 基线快照改落当轮 round-N/。

**A-3 S4「重评对象 = 修订后整合报告包 + 台账」与 §3 输入包构成表述不一致**
- 位置：plan-r2.md S4（L26）vs §3 循环语义段（L33）
- 摘录：S4 "下一轮自 S3 起点再入（重评对象 = 修订后整合报告包 + 台账，被评 10 文件不变，评分口径不变）"；§3 "评估者输入包按 §5 构成（评估标准 + 重评对象 + 上游摘要 + 输出格式），不含历轮报告（§3 隔离）"
- 问题：两处对第 2 轮评估者可见对象的界定不一致。台账（§6.2）为仲裁者持有的跨轮持久文件，含全部历轮问题与来源视角标注；若按 S4 字面将台账并入「重评对象」，评估者将收到跨视角信息，违反约束③隔离。执行时以更具体的 §3 输入包构成为准（可消歧），但计划内部判定口径不一致属可执行性缺陷。
- 改进：S4 表述改为「重评对象 = 修订后整合报告包（台账仅作仲裁侧 S3/S4 核验对象，不进入评估者输入包）」，与 §3 对齐。
