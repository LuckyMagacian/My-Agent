## 3. 拆解依据

- 按「盘点 → 独立评估 → 仲裁汇总 → 收敛定稿」线性拆解：五视角评估的独立性与证据质量依赖盘点阶段把评估对象与标准钉死（S1 前置）；仲裁汇总依赖五份报告的齐备（S3 依赖 S2）——替代拆法（先汇总后补视角）会破坏评估者独立性，已排除；
- S2 并行派发而非串行：五视角相互隔离是模式契约（§3），并行不产生信息通道，且降低总耗时；
- 交付物形态选择「整合评估报告」而非多文件合集：任务指令目标为「产出评估报告」，五份视角报告为支撑材料随轮落盘，整合报告为定稿交付物（与 v1.7 评估先例一致）；
- **循环语义**：本实例被评对象（10 文件）不可修改，故执行阶段第 2 轮起的重评对象为「修订后整合报告包」（整合报告的准确性、覆盖性、证据质量），而非重评 10 文件本身；评估者输入包按 §5 构成（评估标准 + 重评对象 + 上游摘要 + 输出格式），不含历轮报告（§3 隔离）；被评文件本身存在阻断级问题（评估发现）时，问题记入台账并如实写入整合报告，属评估成果而非可修对象，无法闭合时按升级人工路径处置；
- **台账时序**（§6.2）：S3 仲裁时登记台账，S4 收敛判定时核验（首轮新建台账，阻断/重要级条目闭合状态以「已登记待核验」标注，收敛判定时核验）；
- 不设「修正组件文件」步骤：任务指令范围明确为只读评估，组件文件的整改属于评估后的后续轮次（本实例范围外）。

## 5. 风险与偏离预案

| 风险 | 预案 |
| --- | --- |
| 评估者因文件量大遗漏部分文件 | 输入包显式列出 10 文件清单与各文件改动要点；整合仲裁时按「文件维度 + 一致性维度」双维核验覆盖完整性，遗漏视角退回补评（补派输入包与首轮一致，含取材边界声明，不引用其他视角结论） |
| 视角间评分口径漂移 | 各视角评估标准在 S1 钉死并注入（含维度分解）；仲裁时对评分差距 > 2 分的视角核验维度分解依据 |
| 评估发现问题但整合报告遗漏 | S3 整合按问题台账逐条对照；整合报告问题清单以台账为准（§6.2） |
| 组件文件被误修改 | 交付物模板与输入包显式声明「评估仅留痕，不改动任何组件文件」；S4 复跑基线快照命令（`git status --porcelain` + `git diff HEAD -- <10 文件>`）与 S1 基线比对，比对范围限定 10 文件、排除 `.autoflow/` |
| 评估者 Subagent 失败 / 超时 / 空输出 | 以相同输入重试 1 次；仍失败 → 升级人工，不静默跳过（§7） |
| 当轮报告缺失（循环中断） | 按「轮次内补齐」原则（§7）：凭落盘文件核对应到/已到报告清单，仅补派缺失视角，不整轮重来；补派仍失败按上行预案升级人工 |
| 未收敛循环空转 | S4 三态出口 + 停滞检测（§6）兜底：连续 2 轮未建议收敛视角评分无提升 → 停滞 → 达上限/停滞升级人工 |
