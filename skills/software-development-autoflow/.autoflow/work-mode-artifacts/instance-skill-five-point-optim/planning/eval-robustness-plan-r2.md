## 2. 问题清单

### 建议级（CONSIDER）

#### R2-S-1：S4 基线比对检出差异后缺恢复行动

- **位置**：[plan-r2.md#L48-L48](/Users/whiteyang/aiCoder/My-Agent/skills/software-development-autoflow/.autoflow/work-mode-artifacts/instance-skill-five-point-optim/planning/plan-r2.md)
- **原文摘录**：
  > 组件文件被误修改 | 交付物模板与输入包显式声明「评估仅留痕，不改动任何组件文件」；S4 复跑基线快照命令（`git status --porcelain` + `git diff HEAD -- <10 文件>`）与 S1 基线比对，比对范围限定 10 文件、排除 `.autoflow/`
- **问题描述**：该风险条目的预案仅包含**预防**（声明）和**检测**（S4 比对），但未定义检测到差异后的**恢复行动**。若 `git diff HEAD -- <10 文件>` 比对结果与基线不一致，当前计划未说明执行者如何处理（应中止当前轮次、记录违规事实、升级人工调查差异来源）。
- **改进建议**：在风险条目的预案中补充恢复行动：「比对差异 → 记录差异至产物日志 → 中止当前轮收敛判定 → 升级人工（§7）」；或在 S4 完成判据中追加「基线无差异检测通过⇒若差异非空，视同组件文件被误修改，按 §7 升级人工」。

#### R2-S-2：单视角 Subagent 永久失败后整体流程路径未明确

- **位置**：[plan-r2.md#L49-L49](/Users/whiteyang/aiCoder/My-Agent/skills/software-development-autoflow/.autoflow/work-mode-artifacts/instance-skill-five-point-optim/planning/plan-r2.md)
- **原文摘录**：
  > 评估者 Subagent 失败 / 超时 / 空输出 | 以相同输入重试 1 次；仍失败 → 升级人工，不静默跳过（§7）
- **问题描述**：S2 采用「五视角并行派发」，若其中 1 个视角的 Subagent 重试后仍失败则「升级人工」。但「升级人工」的语义在当前计划中不明确：是指**该视角单独升级人工**（其他 4 个已完成视角继续参与仲裁汇聚，缺失视角标注为「人工补评待办」），还是**整个评估流程升级人工**（废弃 4 个已完成视角的工作）？前者效率损失小，后者代价过大。从健壮性角度，应优先保护已完成工作的价值。
- **改进建议**：在 §5 风险条目的预案或 §3 拆解依据中补充明确：「单视角 Subagent 重试仍失败后，该视角标记为『升级人工补评中』，其他已完成的 4 个视角正常进入 S3 仲裁汇总；S4 收敛判定时若该视角报告仍未补全，该视角评分记入台账但不计入收敛条件中的视角评分门槛（人工补评完成后补正）」。或者至少说明：升级人工是针对该视角而非整体流程。
