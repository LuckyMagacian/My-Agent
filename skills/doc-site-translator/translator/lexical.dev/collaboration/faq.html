Collaboration FAQ

真相来源：Lexical State、Yjs 和应用数据库 #

建议将 Yjs model 视为 Lexical 协作的真相来源。虽然文档可以存储在数据库中以进行索引，但 Yjs model 对于没有互联网访问权限的客户端可靠地加入并与服务器同步至关重要。

或者，可以将数据库视为真相来源，这需要仔细管理 session ID 和客户端连接与断开时的内容同步。

Yjs 作为真相来源 #

优点：

  • 离线客户端可以稍后可靠地同步
  • 内置冲突解决机制
  • 实时同步效率高

缺点：

  • 需要持久化 Yjs 文档
  • 数据库中的内容可能与 Yjs model 不同步

数据库作为真相来源 #

优点：

  • 集中控制内容
  • 易于索引和搜索
  • 与现有系统集成更简单

缺点：

  • 需要仔细管理 session ID
  • 客户端连接和断开时需要同步内容
  • 离线场景更复杂
💡 推荐

对于大多数协作编辑场景，建议将 Yjs model 作为主要真相来源，同时可选地将内容持久化到数据库以进行索引和备份。

同步策略 #

在协作编辑中，您需要考虑以下同步场景：

  1. 初始加载 - 客户端首次连接时获取文档状态
  2. 实时更新 - 多个客户端同时编辑时的冲突解决
  3. 离线重连 - 客户端离线后重新连接的同步
  4. 持久化 - 将文档状态保存到服务器

连接管理 #

使用 TOGGLE_CONNECT_COMMAND 控制连接状态：

// 断开连接（例如用户离线时）
editor.dispatchCommand(TOGGLE_CONNECT_COMMAND, false);

// 重新连接
editor.dispatchCommand(TOGGLE_CONNECT_COMMAND, true);

使用 CONNECTED_COMMAND 监听连接状态变化：

editor.registerCommand(CONNECTED_COMMAND, (isConnected) => {
  if (isConnected) {
    console.log('已连接到协作服务器');
  } else {
    console.log('与协作服务器断开连接');
  }
  return false;
}, 0);

冲突解决 #

Yjs 使用 CRDT（Conflict-free Replicated Data Types）自动处理冲突。当多个客户端同时编辑同一位置时，Yjs 会自动合并更改。Lexical 的 Yjs binding 确保这些合并后的更改正确反映在编辑器中。

性能优化 #

对于大型文档或高频率编辑，考虑以下优化：

  • 使用 excludedProperties 排除不需要同步的属性
  • 配置合适的撤销/重做 timeout
  • 使用 debounce 控制保存频率
  • 考虑使用 V2 binding（实验性）以提高性能

嵌套编辑器与协作 #

使用 LexicalNestedComposer 时，如果 collaboration plugin 处于活动状态且 skipCollabChecks 未设置为 true，嵌套编辑器的子组件将不会渲染，直到 collaboration 准备就绪。

<LexicalNestedComposer
  initialConfig={nestedConfig}
  skipCollabChecks={true}  // 跳过协作准备检查
>
  <RichTextPlugin ... />
</LexicalNestedComposer>

Provider 选择 #

Yjs providers 处理客户端通信、awareness 管理和离线数据存储的复杂性。常用选项：

Provider 适用场景 特点
y-websocket 实时协作 简单易用，支持持久化
y-indexeddb 离线编辑 浏览器本地存储
WebrtcProvider 点对点协作 无需中心服务器
Hocuspocus 企业级应用 可扩展、支持钩子

Awareness 功能 #

Yjs awareness 用于跟踪协作用户的状态，包括：

  • 用户名称和光标颜色
  • 当前光标位置和选区
  • 用户是否在线

Provider 的 awareness 属性提供访问这些信息：

provider.awareness.setLocalStateField('user', {
  name: 'Alice',
  color: '#FF0000',
});

provider.awareness.on('change', () => {
  const states = provider.awareness.getStates();
  // 更新用户列表...
});
