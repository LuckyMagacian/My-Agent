Selection

Selection 类型 #

Lexical 的 Selection 是 EditorState 的一部分。这意味着对于每次更新或编辑器更改，Selection 始终与 EditorState 的节点树保持一致。

在 Lexical 中，有四种可能的 Selection 类型：

  • RangeSelection
  • NodeSelection
  • TableSelection（在 @lexical/table 中实现）
  • null

可以实现自己的 Selection 类型来实现 BaseSelection，但这通常不建议。

RangeSelection #

这是最常见的 Selection 类型，是浏览器 DOM Selection 和 Range API 的规范化。RangeSelection 包含三个主要属性：

  • anchor 表示一个 RangeSelection 点
  • focus 表示一个 RangeSelection 点
  • format 数字位标志，表示任何活动的文本格式

anchor 和 focus 点都指向一个表示编辑器特定部分的对象。RangeSelection 点的主要属性是：

  • key 表示所选 Lexical 节点的 NodeKey
  • offset 表示在其所选 Lexical 节点内的位置。对于 text 类型，这是字符；对于 element 类型，这是 ElementNode 内的子索引
  • type 表示 element 或 text

NodeSelection #

NodeSelection 表示多个任意节点的选择。例如，同时选择三个图片。

getNodes() 返回一个包含所选 LexicalNodes 的数组。

TableSelection #

TableSelection 表示类似表格的网格选择。它存储选择发生的父节点的 key 以及起点和终点。TableSelection 包含三个主要属性：

  • tableKey 表示选择发生的父节点 key
  • anchor 表示一个 TableSelection 点
  • focus 表示一个 TableSelection 点

例如，选择 row = 1 col = 1 到 row 2 col = 2 的表格可以存储为：

  • tableKey = 2 表格 key
  • anchor = 4 表格单元格（key 可能变化）
  • focus = 10 表格单元格（key 可能变化）

注意 anchor 和 focus 点的工作方式与 RangeSelection 相同。

null #

这表示编辑器没有任何活动 Selection。这常见于编辑器失去焦点或 Selection 移动到页面上的另一个编辑器时。这也可能发生在尝试选择编辑器空间内的非可编辑组件时。

使用 Selection #

可以使用从 lexical 包导出的 $getSelection() 辅助函数找到 Selection。此函数可在 update、read 或 command listener 中使用。

import {$getSelection, SELECTION_CHANGE_COMMAND} from 'lexical';

editor.update(() => {
  const selection = $getSelection();
});

editorState.read(() => {
  const selection = $getSelection();
});

// SELECTION_CHANGE_COMMAND 在 Lexical 编辑器内 Selection 更改时触发。
editor.registerCommand(SELECTION_CHANGE_COMMAND, () => {
  const selection = $getSelection();
});

在某些情况下，您可能想要创建新的 Selection 类型并将编辑器 Selection 设置为该类型。这只能在 update 或 command listener 中完成。

import {$setSelection, $createRangeSelection, $createNodeSelection} from 'lexical';

editor.update(() => {
  // 设置一个 range selection
  const rangeSelection = $createRangeSelection();
  $setSelection(rangeSelection);

  // 您也可以通过调用 Lexical 节点上的某些 selection 方法
  // 间接创建 range selection。
  const someNode = $getNodeByKey(someKey);

  // 在 element 节点上，这将创建一个类型为 "element" 的 RangeSelection，
  // 引用与 element 内子节点相关的偏移量。
  // 在 text 节点上，这将创建一个类型为 "text" 的 RangeSelection，
  // 引用文本字符偏移量。
  someNode.select();
  someNode.selectPrevious();
  someNode.selectNext();

  // 您可以在任何节点上使用此方法。
  someNode.selectStart();
  someNode.selectEnd();

  // 设置一个 node selection
  const nodeSelection = $createNodeSelection();
  // 向 selection 添加一个节点 key。
  nodeSelection.add(someKey);
  $setSelection(nodeSelection);

  // 您也可以通过将其设置为 `null` 来清除 selection。
  $setSelection(null);
});

Focus #

您可能会注意到，当您执行 editor.update 或 editor.dispatchCommand 时，如果有 selection 且编辑器是可编辑的，编辑器可以"抢夺焦点"。这是因为 Lexical selection 在协调期间被同步到 DOM selection，浏览器的焦点跟随其 DOM selection。

如果您想要在不更改 selection 的情况下对编辑器进行更新或派发命令，可以使用 SKIP_DOM_SELECTION_TAG update 标签（在 v0.22.0 中添加）：

// 从 editor.update 或 command listener 调用此方法
$addUpdateTag(SKIP_DOM_SELECTION_TAG);

如果您想要在 dispatchCommand 处理期间添加此标签，可以将其包装在 editor.update 中：

// 注意：如果您已经在 command listener 或 editor.update 中，
//       *不要*嵌套第二个 editor.update！嵌套的 update 具有
//       混乱的语义（dispatchCommand 将重新使用
//       当前 update 而不嵌套）
editor.update(() => {
  $addUpdateTag(SKIP_DOM_SELECTION_TAG);
  editor.dispatchCommand(/* … */);
});

如果您必须支持较旧版本的 Lexical，可以在 update 或 dispatch 期间将编辑器标记为不可编辑：

// 注意：此代码应该*在*您的 update 或 command listener 外部，例如
//       直接在 DOM event listener 中
const prevEditable = editor.isEditable();
editor.setEditable(false);
editor.update(
  () => {
    // 在此处运行您的 update 代码或 editor.dispatchCommand
  },
  {
    onUpdate: () => {
      editor.setEditable(prevEditable);
    },
  },
);

跨 Shadow Boundary 读取 Selection #

如果您的插件直接读取 DOM Selection —— 通过 Selection.anchorNode、Selection.getRangeAt(0) 或类似方式 —— 并且编辑器的 contentEditable 位于 ShadowRoot 内，浏览器会将这些读取重新定位到 shadow host。请参阅 Shadow DOM 和 iframes 了解 shadow-aware 的辅助函数（getDOMSelectionPoints、getDOMSelectionRange 等），它们返回未重新定位的边界点；在普通 light DOM 中它们会回退到标准读取，因此在实际将编辑器挂载到 shadow tree 之前无需做任何处理。
