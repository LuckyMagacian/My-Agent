Working with DOM Events

有时，在使用 Lexical 时，可能需要或有用的是将 DOM Event Listener 附加到 Lexical 控制的底层 DOM 节点。例如，您可能想在用户将鼠标悬停在特定节点上时显示弹出窗口，或在用户点击节点时打开模态框。这些用例（以及许多其他用例）都可以通过原生 DOM Event Listeners 完成。在 Lexical 控制的节点上监听 DOM Events 有三种主要方式：

1. Event Delegation #

在编辑器内处理事件的一种方法是在编辑器根元素（Lexical 附加到的 contentEditable）上设置 listener。您可以使用 Root Listener 来完成此操作。

function myListener(event) {
    // 您可能希望在此处过滤事件目标
    // 以仅包含某些类型的 DOM 节点上的点击。
    alert('Nice!');
}

const removeRootListener = editor.registerRootListener((rootElement) => {
    // 将 listener 添加到当前根元素
    rootElement.addEventListener('click', myListener);
    // 从旧根元素移除 listener - 确保 myListener 的引用
    // 是稳定的，这样移除才能工作并避免内存泄漏。
    return () => rootElement.removeEventListener('click', myListener);
});

// 清理 listener - 如果您使用 React，从 useEffect 回调返回此函数。
removeRootListener();

这可能是处理某些用例的简单、高效方法，因为不需要单独将 listener 附加到每个 DOM 节点。

2. Directly Attach Handlers #

在某些情况下，将事件处理器直接附加到每个特定节点的底层 DOM 节点可能更好。使用这种方法，您通常不需要在处理器中过滤事件目标，这可以使操作更简单。这也将保证您的处理器不会为您不关心的事件运行。此方法通过 Mutation Listener 实现。

const registeredElements: WeakSet<HTMLElement> = new WeakSet();
const removeMutationListener = editor.registerMutationListener(nodeType, (mutations) => {
    editor.getEditorState().read(() => {
        for (const [key, mutation] of mutations) {
            const element: null | HTMLElement = editor.getElementByKey(key);
            if (
                // Updated 可能是移动，因此可能意味着创建了新的 DOM 元素。
                // 在这种情况下，我们也需要添加事件 listener。
                (mutation === 'created' || mutation === 'updated') &&
                element !== null &&
                !registeredElements.has(element)
            ) {
                registeredElements.add(element);
                element.addEventListener('click', (event: Event) => {
                    alert('Nice!');
                });
            }
        }
    });
});

// 清理 listener - 如果您使用 React，从 useEffect 回调返回此函数。
removeMutationListener();

请注意，这里我们不需要担心清理，因为 Lexical 将取消引用底层 DOM 节点并允许 JavaScript 运行时垃圾回收器清理它们的 listener。

3. Use NodeEventPlugin #

如果您使用 React，我们将方法 #2 包装成了一个简单的 LexicalComposer plugin，您可以使用它来达到相同的效果，而无需担心细节：

<LexicalComposer>
    <NodeEventPlugin
        nodeType={LinkNode}
        eventType={'click'}
        eventListener={(e: Event) => {
            alert('Nice!');
        }}
    />
</LexicalComposer>

如果编辑器位于 shadow root 或 iframe 内，请参阅 Shadow DOM 和 iframes 了解通过 shadow boundary 读取 event.target 的辅助函数 —— 浏览器将其重新定位到附加在 boundary 上方的 listener 的 shadow host，因此普通的 event.target 不会匹配编辑器内的节点。
