Node Traversals with NodeCaret

NodeCaret 提供了一种统一且高效的方式来遍历文档树，使正确实现遍历并避免空节点和折叠 selection 的边缘情况变得更加容易。

这些新的低级函数都被设计为协同工作，作为一个功能齐全且相对轻量级的 API 在核心中使用，允许我们逐步解决一些边缘情况，然后简化和缩小代码。我们期望更高级的实用程序将在 @lexical/utils 或其他模块中开发和发布。当前开销在生产环境中应小于 3kB。

NodeCaret API 在 lexical v0.25.0 中引入。

概念 #

NodeCaret 的核心概念是，您可以通过使用 origin 节点、指向相邻节点（next 或 previous）的 direction，以及指定箭头是指向 sibling（sibling）还是 child（child）的 type 来表示文档中的任何特定点。

所有这些类型都有一个 D 类型参数，必须是 CaretDirection，因此您不会意外混淆 next 和 previous caret。许多类型还有一个 T 类型参数，编码 origin 节点的类型。

提示

Caret 的方法被设计为操作指定方向上附加到 origin 的节点，而不是 origin 本身。例如，此代码是无操作，因为它将附加一个节点到 origin，然后删除刚附加的节点。

// origin 不受影响（除了被标记为 dirty）
caret.insert($createTextNode('no-op')).remove();
警告

Caret 是不可变的，设计用于低级使用。Caret 不会尝试根据文档更改自动更新（这是使用 RangeSelection 时常见的 bug 来源）。预期会更改文档结构的函数和方法将始终返回可能的新 caret。

Caret 的 origin 是构造它的对象的精确版本，该 origin 上的所有访问器方法通常会调用 origin.getLatest()，因此操作将看到最新版本。

NodeCaret #

NodeCaret 是任何 SiblingCaret 或任何 ChildCaret。

通常使用 $getChildCaretOrSelf($getSiblingCaret(origin, direction)) 构造，当 origin 是 ElementNode 时返回 ChildCaret。

SiblingCaret #

SiblingCaret 是指向 origin sibling 的 caret。

使用 $getSiblingCaret(origin: LexicalNode, direction: CaretDirection) 构造。

next 方向指向右侧，previous 方向指向左侧。

方法→ direction: 'next'← direction: 'previous'
getParentAtCaret()origin.getParent()origin.getParent()
getNodeAtCaret()origin.getNextSibling()origin.getPreviousSibling()
insert(node)origin.insertAfter(node)origin.insertBefore(node)

ChildCaret #

ChildCaret 是指向 origin 第一个或最后一个 child 的 caret。

使用 $getChildCaret(origin: ElementNode, direction: CaretDirection) 构造。

next 方向指向第一个 child，previous 方向指向最后一个 child。

方法↘ direction: 'next'↙ direction: 'previous'
getParentAtCaret()originorigin
getNodeAtCaret()origin.getFirstChild()origin.getLastChild()
insert(node)origin.splice(0, 0, node)origin.append(node)

CaretRange #

CaretRange 包含一对指向相同方向的 PointCaret。它在目的上等效于 RangeSelection，是您通常用于深度优先遍历的内容。

使用 $getCaretRange(anchor, focus)、$caretRangeFromSelection(selection) 或 $extendCaretToRange(anchor) 构造。

  • anchor 是范围的开始，通常是 selection 的起源，它被"锚定"在原位，因为当 selection 增长或缩小时，只有 focus 会移动。
  • focus 是范围的结束，闪烁光标所在的位置，用户当前的焦点。

Anchor 和 focus 必须指向相同方向。anchor 指向范围中的第一个节点，focus 指向不在范围中的第一个节点。

警告

如果您正在迭代 CaretRange，您必须单独考虑 getTextSlices()，它们不包括在迭代中。这样您就不必在每一步都考虑 TextPointCaretSlice。它们是只能出现在开始和/或结束的字面边缘情况，通常有特殊处理（例如分割而不是删除）。

遍历策略 #

Adjacent Caret Traversals

使用 NodeCaret 进行遍历的最低级构建块是相邻 caret 遍历，由 NodeCaret 的方法直接支持：

  • getAdjacentCaret() - 获取指定方向上附加到 origin 的节点的 SiblingCaret。如果没有附加节点，返回 null。
  • getParentCaret(rootMode) - 获取相同方向上 origin 父节点的 SiblingCaret。如果没有父节点，或根据 rootMode 父节点是 root，返回 null。rootMode 可以是 'root' 只为 RootNode 返回 null，或 'shadowRoot' 为 RootNode 或任何 isShadowRoot() 返回 true 的 ElementNode 父节点返回 null。
  • getChildCaret() - 获取此 origin 的 ChildCaret，如果 origin 不是 ElementNode 则返回 null。如果 caret 已经是 ChildCaret，将返回 this。

Depth First Caret Traversals

深度优先 caret 遍历的策略是使用相邻 caret 遍历，并在遇到 ElementNode origin 时立即使用 ChildCaret。此策略生成所有可能的 caret，但遍历中的每个 ElementNode 可能被 yield 一次或两次（进入时是 ChildCaret，离开时是 SiblingCaret）。允许您查看 ElementNode 是否部分包含在范围中是这个抽象存在的原因之一。

术语 #

Caret

选择 Caret 这个术语是因为它是文本文档中特定点的简洁且具体的术语。Lexical 是"可扩展的文本编辑器框架"，因此文档中的导航使用与文本相关的术语是有意义的。大多数其他术语如 Cursor 或 Point 在 Lexical 中已有含义或不够具体。

Origin

Origin 是 NodeCaret 的参考节点。绝对坐标通过组合此 origin 节点和指向相邻节点所在位置（或可能在的位置）的"箭头"来确定。"箭头"由 caret 的 direction 和 type 确定。

Direction

选择 'next' 和 'previous' 作为方向主要是为了匹配 DOM 和 Lexical 中存在的现有方法如 getNextSibling()。使用其他词语如 'left' 和 'right' 会有歧义，因为文本方向可以是双向的，并且已经使用从左到右和从右到左的术语。
