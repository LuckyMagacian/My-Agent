Nodes

Base Nodes #

Nodes 是 Lexical 的核心概念。它们不仅构成可视化编辑器视图（作为 EditorState 的一部分），还表示编辑器在任何时刻存储内容的底层数据模型。Lexical 有一个单一的核心基础节点，称为 LexicalNode，它在内部被扩展以创建 Lexical 的五个基础节点：

  • RootNode
  • LineBreakNode
  • ElementNode
  • TextNode
  • DecoratorNode

在这些基础节点中，有三个可以被扩展以创建新类型的节点：

  • ElementNode
  • TextNode
  • DecoratorNode

RootNode #

在 EditorState 中只有一个 RootNode，它始终位于顶部并表示 contenteditable 本身。这意味着 RootNode 没有父节点或兄弟节点。它不能被子类化或替换。

  • 要获取整个编辑器的文本内容，您应该使用 rootNode.getTextContent()。
  • 为了避免选区问题，Lexical 禁止将文本节点直接插入到 RootNode 中。

Semantics and Use Cases #

与其他 ElementNode 子类不同，RootNode 具有特定的特性和限制以维护编辑器的完整性：

  1. Non-extensibility
    RootNode 不能被子类化或用自定义实现替换。它被设计为编辑器架构的固定部分。

  2. Exclusion from Mutation Listeners
    RootNode 不参与 mutation listeners。相反，使用 root-level 或 update listener 来观察文档级别的更改。

  3. Compatibility with Node Transforms
    虽然 RootNode 在传统意义上不是"文档的一部分"，但在某些情况下它可能会出现，例如在序列化期间或应用 node transforms 时。对 RootNode 的 node transform 将在每个 node transform 循环结束时调用。这在您需要类似 update listener 但在编辑器状态协调之前发生的情况下非常有用。

  4. Document-Level Metadata
    如果您尝试使用 RootNode 存储文档级元数据（例如 undo/redo 支持），请使用 NodeState API。

根据设计，RootNode 作为编辑器内容的容器，而不是文档逻辑结构的活跃部分。这种方法简化了序列化等操作，并将焦点保持在内容节点上。

LineBreakNode #

您的文本节点中永远不应该有 '\n'，相反，您应该使用 LineBreakNode，它表示 '\n'，更重要的是，可以在浏览器和操作系统之间一致地工作。

ElementNode #

用作其他节点的父节点，可以是块级（ParagraphNode、HeadingNode）或内联（LinkNode）。具有各种定义其行为的方法，可以在扩展期间覆盖（isInline、canBeEmpty、canInsertTextBefore 等）。

TextNode #

包含文本的叶节点类型。它还包括一些文本特有的属性：

  • format：任意组合的 bold、italic、underline、strikethrough、code、highlight、subscript 和 superscript
  • mode：
    • token - 作为不可变节点，无法更改其内容，一次性删除
    • segmented - 其内容按段删除（一次一个单词），它是可编辑的，但节点在内容更新后变为非分段
  • style：可用于将内联 CSS 样式应用于文本

DecoratorNode #

包装节点，用于在编辑器内插入任意视图（组件）。Decorator node 渲染是框架无关的，可以输出来自 React、vanilla js 或其他框架的组件。

Node Properties #

💡 提示

如果您使用 Lexical v0.26.0 或更高版本，应该考虑使用 NodeState API 而不是在子类上直接定义属性。NodeState 自动支持 afterCloneFrom、exportJSON 和 updateFromJSON，需要更少的样板代码和一些额外的好处。您可能会发现某些情况下根本不需要子类，因为您的 NodeState 可以临时应用于任何节点。

Lexical nodes 可以有属性。这些属性也必须是 JSON 可序列化的，因此您永远不应该将函数、Symbol、Map、Set 或任何具有与内置类型不同原型对象分配给节点。null、undefined、number、string、boolean、{} 和 [] 都是可以分配给节点的属性类型。

按照惯例，我们使用 __（双下划线）前缀属性，以便明确这些属性是私有的，应该避免直接访问。我们选择 __ 而不是 _，因为某些构建工具会混淆和压缩单个 _ 前缀属性以提高代码大小。但是，如果您将节点暴露给构建外部进行扩展，这就会出问题。

如果您添加一个预期可修改或可访问的属性，则应该始终为该属性在节点上创建一组 get*() 和 set*() 方法。在这些方法内部，您需要调用一些非常重要的方法以确保与 Lexical 内部不可变系统的一致性。这些方法是 getWritable() 和 getLatest()。

我们建议您的构造函数应始终支持零参数实例化，以便更好地支持协作并减少所需的样板代码量。您可以始终使用必需参数定义您的 $create* 函数。

如果您的节点将参与 @lexical/yjs 协作，并且您将自定义数据存储为直接属性而不是 NodeState，请在构造函数中无条件初始化每个属性，包括 undefined 默认值。像 __foo?: string 这样的可选属性语法而没有赋值是不够的，因为新构造的实例不会有该属性来同步。有关详细信息，请参阅 collaboration guide。

import type {NodeKey} from 'lexical';

class MyCustomNode extends SomeOtherNode {
  __foo: string;

  constructor(foo: string = '', key?: NodeKey) {
    super(key);
    this.__foo = foo;
  }

  setFoo(foo: string): this {
    // getWritable() creates a clone of the node
    // if needed, to ensure we don't try and mutate
    // a stale version of this node.
    const self = this.getWritable();
    self.__foo = foo;
    return self;
  }

  getFoo(): string {
    // getLatest() ensures we are getting the most
    // up-to-date value from the EditorState.
    const self = this.getLatest();
    return self.__foo;
  }
}

最后，所有节点都应该有 static getType()、static clone() 和 static importJSON() 方法。Lexical 使用 type 在反序列化期间能够用其关联的类原型重建节点（对于复制+粘贴很重要！）。Lexical 使用 cloning 来确保创建新 EditorState 快照之间的一致性。

在上面的示例基础上扩展这些方法：

interface SerializedCustomNode extends SerializedLexicalNode {
  foo?: string;
}

class MyCustomNode extends SomeOtherNode {
  __foo: string;

  static getType(): string {
    return 'custom-node';
  }

  static clone(node: MyCustomNode): MyCustomNode {
    // If any state needs to be set after construction, it should be
    // done by overriding the `afterCloneFrom` instance method.
    return new MyCustomNode(node.__foo, node.__key);
  }

  static importJSON(
    serializedNode: LexicalUpdateJSON<SerializedMyCustomNode>,
  ): MyCustomNode {
    return new MyCustomNode().updateFromJSON(serializedNode);
  }

  constructor(foo: string = '', key?: NodeKey) {
    super(key);
    this.__foo = foo;
  }

  updateFromJSON(
    serializedNode: LexicalUpdateJSON<SerializedMyCustomNode>,
  ): this {
    const self = super.updateFromJSON(serializedNode);
    return typeof serializedNode.foo === 'string'
      ? self.setFoo(serializedNode.foo)
      : self;
  }

  exportJSON(): SerializedMyCustomNode {
    const serializedNode: SerializedMyCustomNode = super.exportJSON();
    const foo = this.getFoo();
    if (foo !== '') {
      serializedNode.foo = foo;
    }
    return serializedNode;
  }

  setFoo(foo: string): this {
    const self = this.getWritable();
    self.__foo = foo;
    return self;
  }

  getFoo(): string {
    const self = this.getLatest();
    return self.__foo;
  }
}

Creating custom nodes #

如上所述，Lexical 提供了三个可以扩展的基础节点。

你知道吗？

像 ElementNode 这样的节点已经由 Lexical 在核心中扩展，例如 ParagraphNode 和 RootNode！

Extending ElementNode #

以下是如何扩展 ElementNode 的示例：

import {ElementNode, LexicalNode} from 'lexical';

export class CustomParagraph extends ElementNode {
  static getType(): string {
    return 'custom-paragraph';
  }

  static clone(node: CustomParagraph): CustomParagraph {
    return new CustomParagraph(node.__key);
  }

  createDOM(): HTMLElement {
    // Define the DOM element here
    const dom = document.createElement('p');
    return dom;
  }

  updateDOM(prevNode: this, dom: HTMLElement, config: EditorConfig): boolean {
    // Returning false tells Lexical that this node does not need its
    // DOM element replacing with a new copy from createDOM.
    return false;
  }
}

为您的自定义 ElementNode 提供一些 $ 前缀的实用函数也是良好的习惯，以便其他人可以轻松消费和验证节点是您的自定义节点。以下是您如何为上面的示例做到这一点：

export function $createCustomParagraphNode(): CustomParagraph {
  return $applyNodeReplacement(new CustomParagraph());
}

export function $isCustomParagraphNode(
  node: LexicalNode | null | undefined,
): node is CustomParagraph {
  return node instanceof CustomParagraph;
}

Extending TextNode # 

export class ColoredNode extends TextNode {
  __color: string;

  constructor(text: string, color: string, key?: NodeKey): void {
    super(text, key);
    this.__color = color;
  }

  static getType(): string {
    return 'colored';
  }

  static clone(node: ColoredNode): ColoredNode {
    return new ColoredNode(node.__text, node.__color, node.__key);
  }

  createDOM(config: EditorConfig): HTMLElement {
    const element = super.createDOM(config);
    element.style.color = this.__color;
    return element;
  }

  updateDOM(prevNode: this, dom: HTMLElement, config: EditorConfig): boolean {
    const isUpdated = super.updateDOM(prevNode, dom, config);
    if (prevNode.__color !== this.__color) {
      dom.style.color = this.__color;
    }
    return isUpdated;
  }
}

export function $createColoredNode(text: string, color: string): ColoredNode {
  return $applyNodeReplacement(new ColoredNode(text, color));
}

export function $isColoredNode(
  node: LexicalNode | null | undefined,
): node is ColoredNode {
  return node instanceof ColoredNode;
}

Extending DecoratorNode # 

export class VideoNode extends DecoratorNode<ReactNode> {
  __id: string;

  static getType(): string {
    return 'video';
  }

  static clone(node: VideoNode): VideoNode {
    return new VideoNode(node.__id, node.__key);
  }

  constructor(id: string, key?: NodeKey) {
    super(key);
    this.__id = id;
  }

  createDOM(): HTMLElement {
    return document.createElement('div');
  }

  updateDOM(): false {
    return false;
  }

  decorate(): ReactNode {
    return <VideoPlayer videoID={this.__id} />;
  }
}

export function $createVideoNode(id: string): VideoNode {
  return $applyNodeReplacement(new VideoNode(id));
}

export function $isVideoNode(
  node: LexicalNode | null | undefined,
): node is VideoNode {
  return node instanceof VideoNode;
}

使用 useDecorators、PlainTextPlugin 和 RichTextPlugin 会为每个 DecoratorNode 执行 React.createPortal(reactDecorator, element)，其中 reactDecorator 是 DecoratorNode.prototype.decorate 返回的内容，element 是 DecoratorNode.prototype.createDOM 返回的 HTMLElement。

The rest of the boilerplate #

使用此扩展方法时，还需要实现以下方法：

  • static clone（始终需要 - 已在上面的示例中）
  • static importFromJSON（始终需要）
  • updateFromJSON（如果定义了任何自定义属性）
  • afterCloneFrom（如果定义了任何不从 static clone 继承的自定义属性）
  • exportJSON（如果定义了任何自定义属性）

Creating custom nodes with $config and NodeState #

在 Lexical v0.33.0 中，添加了一种定义自定义节点的新方法，以减少样板代码并添加 NodeState API 所使用的功能。

以下部分展示了如何将前面的示例重构为使用最新功能，减少样板代码。

请注意，由于这些示例使用 NodeState 和 $config，它们将自动获得以下方法的完整且正确的实现：

  • static clone
  • static importFromJSON
  • updateFromJSON
  • afterCloneFrom
  • exportJSON

Best Practices #

  • 任何自定义节点的构造函数必须没有必需参数。这是 @lexical/yjs 支持、$create 支持所必需的，并允许消除样板静态 clone 和 importJSON 方法。

    • ✅ constructor(text: string = '', key?: NodeKey)
    • ❌ constructor(text: string, key?: NodeKey)

  • 仅使用 NodeState（而不是直接属性访问）在节点上存储额外数据，允许消除样板 afterCloneFrom、exportJSON 和 updateFromJSON 方法。

Extending ElementNode with $config #

以下是如何使用 $config 扩展 ElementNode 的示例：

import {
  $create,
  type EditorConfig,
  ElementNode,
  type LexicalNode,
} from 'lexical';

export class CustomParagraph extends ElementNode {
  $config() {
    return this.config('custom-paragraph', {extends: ElementNode});
  }

  createDOM(): HTMLElement {
    // Define the DOM element here
    const dom = document.createElement('p');
    return dom;
  }

  updateDOM(prevNode: this, dom: HTMLElement, config: EditorConfig): boolean {
    // Returning false tells Lexical that this node does not need its
    // DOM element replaced with a new one from createDOM.
    return false;
  }
}

为您的自定义节点提供一些 $ 前缀的实用函数也是良好的习惯：

export function $createCustomParagraphNode(): CustomParagraph {
  return $create(CustomParagraph);
}

export function $isCustomParagraphNode(
  node: LexicalNode | null | undefined,
): node is CustomParagraph {
  return node instanceof CustomParagraph;
}
