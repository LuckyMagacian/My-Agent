Named Slots

⚠️ 警告

Named slots 是实验性的。此处描述的 API 标记为 @internal，可能会在没有主要版本更新的情况下更改，序列化和协作格式应被视为不稳定，直到功能稳定。

Named slots 让单个宿主节点（ElementNode 或 DecoratorNode）在其自己的 EditorState 内拥有多个按名称寻址的隔离可编辑区域——Card 的 title、PullQuote 的 quote 和 attribution——在宿主自己的 EditorState 内部。

每个区域有自己的光标和格式，永远不会跨边界合并，Backspace 不会溢出到文档其余部分。

在 named slots 之前，通常的答案是每个区域使用一个嵌套编辑器：每个区域都有自己的 EditorState，因此在区域之间移动节点以及保持历史和协作同步都需要序列化和额外的处理。其他节点形状也不适合：普通 ElementNode 子节点共享一个未分割的链表（区域开头的 Backspace 会将其合并到前一个区域），而 DecoratorNode 是原子性的，因此 Lexical 无法在其内部拥有选区、协作或序列化。使用 named slots，编辑 slot 只是编辑一棵树。

📝 注意

Named slots 是 DOM rendering documentation 中 $getSlotTargetElement / SlotComponent 渲染概念的模型级泛化。每个 ElementNode 已经有一个未命名的子节点通道，$getSlotTargetElement 控制该通道的内容在节点的 DOM 中的附着位置。Named slots 是其旁边额外的、显式命名的通道——对称在于每个都渲染到宿主 DOM 中可控的位置——但它们还携带未命名通道没有的模型级语义：隔离（下面的虚拟 shadow root）、单独的 NodeKey map，以及自己的序列化和协作。

The Model #

宿主保持第二个子通道，一个 slot 名称到 NodeKey 的 Map，与其普通链表子节点分开。slot 值设置了其 slot 宿主指针和 __prev/__next，其中正好有一个非空：getPreviousSibling/getNextSibling 在 slot 边界停止，您只能通过 $getSlotHost 爬出。

slot 链接本身充当宿主和值之间的虚拟不可见 shadow root。隔离是结构性的而不是约定——意外的边界穿越会作为抛出的不变量出现，而不是静默损坏。

Hosts and Values #

任何 ElementNode 或 DecoratorNode 都可以托管 slots。ElementNode 宿主可以将 slots 与普通子节点混合（带有 title slot 加上正则正文段落的 Card）；DecoratorNode 宿主没有子节点通道，所以 slots 是其唯一的可编辑内容（否则是原子性的 PullQuote）。

slot 值是任何非内联 ElementNode 或 DecoratorNode。值的形状决定编辑模型：

  • 裸块（例如 ParagraphNode）作为单行字段行为，在模型、JSON 或 DOM 中没有额外包装器：其虚拟范围正好容纳一个块，所以 Enter 是无操作（宿主可能将其映射为焦点移动），多块粘贴会像 <input> 清理其值那样扁平化为内联内容——剥离换行符，丢弃仅块的装饰器。
  • Shadow-root 容器（isShadowRoot() 返回 true 的 ElementNode）作为多块区域行为，内部有正常的块编辑。

Declaring and Setting Slots #

宿主类在 $config() 中声明其 slot 名称；值通过 $setSlot 附着：

import {
  $create,
  $createParagraphNode,
  $setSlot,
  ElementNode,
} from 'lexical';

class CardNode extends ElementNode {
  $config() {
    return this.config('card', {extends: ElementNode, slots: ['title']});
  }
  createDOM(): HTMLElement {
    return document.createElement('div');
  }
  updateDOM(): boolean {
    return false;
  }
}

function $createCardNode(): CardNode {
  const card = $create(CardNode);
  // Single-line title: the bare paragraph IS the slot value.
  $setSlot(card, 'title', $createParagraphNode());
  // Ordinary body child, edited like any other block.
  return card.append($createParagraphNode());
}

Slot Order #

Slot 顺序是规范的且是派生的，从不存储。在 $config() 中声明的名称按声明顺序首先排序；未声明的名称在其后排序，按 UTF-16 代码单元字典序（普通 JavaScript 字符串比较，与语言环境无关）。$setSlot 在每次写入时重新规范化，所以文档在加载时规范化，并发协作添加在每个客户端上收敛到相同顺序。如果呈现顺序重要，请声明名称。

Rendering #

协调器始终同步渲染每个 slot 子树，但渲染到隐藏的占位符容器——可见性是宿主的显式决定。有三种方法来附着 slot：

  • 同步在 lexical 内：为宿主的节点类注册 $getSlotTargetElement 覆盖（DOM 渲染覆盖，而不是节点方法——这是一个高级钩子）。
  • 命令式：mountSlotContainer 和 unmountSlotContainer 来自 'lexical' 是框架无关的原语（例如从 mutation listener，它在提交后触发）。
  • 从 React chrome：useLexicalSlotRef 钩子来自 '@lexical/react/useLexicalSlotRef' 包装命令式对并返回一个 ref，将 slot 的容器挂载到您的组件中。
