Commands

Commands 是 Lexical 的一个非常强大的功能，让您可以为像 click 或 keyDown 这样的事件注册 listeners，并在任何地方和任何方式上下文响应它们。

此模式对于构建 toolbars 或复杂的 mentions 和 links 插件非常有用，如 TablePlugin，它需要对 keydown、copy 等进行特殊处理。

当注册 command listener 时，您提供一个 priority 并可以返回 true 以将其标记为"已处理"，这会阻止其他 listeners 接收事件。如果命令没有被您显式处理，它可能会在 RichTextPlugin 或 PlainTextPlugin 中默认处理。

Custom Commands #

您可以在 lexical 包中查看所有现有 commands，但如果您需要自己的自定义 command 用于您自己的用例，请查看类型化的 createCommand 函数。

const HELLO_WORLD_COMMAND: LexicalCommand<string> = createCommand('HELLO_WORLD');

editor.registerCommand(
  HELLO_WORLD_COMMAND,
  (payload: string) => {
    console.log(payload); // Hello World!
    return false;
  },
  COMMAND_PRIORITY_EDITOR,
);

editor.dispatchCommand(HELLO_WORLD_COMMAND, 'Hello World!');

Dispatching #

Commands 可以从任何您有访问 editor 的地方派发，如 Toolbar Button、事件 listener 或 Plugin，但大多数核心 commands 从 event listeners 派发。

调用 dispatchCommand 将隐式调用 editor.update() 以触发其 command listeners（如果它不是从 editor.update 内部调用的）。

editor.dispatchCommand(command, payload);

payload 通过 LexicalCommand API 类型化，但它们通常是 DOM Event 用于从事件 listener 派发的 commands。

以下是来自 lexical 的一些真实示例：

editor.dispatchCommand(KEY_ARROW_LEFT_COMMAND, event);
// ...
editor.dispatchCommand(FORMAT_TEXT_COMMAND, 'italic');

以及来自我们 Playground 中 ToolbarPlugin 的另一个示例：

const formatBulletList = () => {
  editor.dispatchCommand(INSERT_UNORDERED_LIST_COMMAND);
};

这后来在 ListPlugin 中处理，将列表插入编辑器：

editor.registerCommand(
  INSERT_UNORDERED_LIST_COMMAND,
  () => {
    $insertList('ul');
    return true;
  },
  COMMAND_PRIORITY_LOW,
);

Registering #

您可以从任何有访问 editor 对象的地方注册 command，但重要的是当不再需要时使用其 remove listener callback 清理 listener。

command listener 将始终从 editor.update() 中调用，因此您可以使用 dollar 函数。您不应该同步从 command listener 内部使用 editor.update()（并且永远不要调用 editor.read() 或 editor.getEditorState()）。如果需要在已经进行更新后读取先前状态，调用 getLatest() 或 node.getPreviousState() 是安全的。

const removeListener = editor.registerCommand(
  COMMAND,
  (payload) => boolean, // Return true to stop propagation.
  priority,
);

// ...
removeListener(); // Cleans up the listener.

一种用于轻松清理的常见模式是在 React useEffect 中返回一个 registerCommand 调用：

useEffect(() => {
  return editor.registerCommand(
    TOGGLE_LINK_COMMAND,
    (payload) => {
      const url: string | null = payload;
      setLink(url);
      return true;
    },
    COMMAND_PRIORITY_EDITOR,
  );
}, [editor]);

如上面和下面所见，registerCommand 的 callback 可以返回 true 以向其他 listeners 表示命令已被处理，传播将被停止。

以下是处理来自 KeyboardPlugin 的 KEY_TAB_COMMAND 的简化示例，用于派发 INDENT_CONTENT_COMMAND 或 OUTDENT_CONTENT_COMMAND：

editor.registerCommand(
  KEY_TAB_COMMAND,
  (payload) => {
    const event: KeyboardEvent = payload;
    event.preventDefault();
    return editor.dispatchCommand(
      event.shiftKey ? OUTDENT_CONTENT_COMMAND : INDENT_CONTENT_COMMAND,
    );
  },
  COMMAND_PRIORITY_EDITOR,
);

注意同一个 KEY_TAB_COMMAND command 也由 TablePlugin 注册，它处理将焦点移动到 TableNode 内的下一个或上一个单元格，但优先级很高（COMMAND_PRIORITY_HIGH），因为此行为非常重要。

Priorities and ordering #

Command listeners 按以下顺序调用，直到 listener 返回 true：

  • 从优先级最高到最低（critical、high、normal、low、editor）
  • 所有 COMMAND_PRIORITY_CRITICAL listeners，最近注册的先调用
  • 所有 COMMAND_PRIORITY_EDITOR listeners，按注册顺序
📝 注意

从 v0.44.0 开始，有新的 COMMAND_PRIORITY_BEFORE_* 优先级可用，这使得在不提高优先级的情况下更容易覆盖默认行为。最佳实践是使用尽可能低的优先级，所以大多数 commands 将用 COMMAND_PRIORITY_EDITOR 注册用于默认行为，然后覆盖该行为的 commands 可以用 COMMAND_PRIORITY_BEFORE_EDITOR 注册。更高的优先级主要用于能够观察但不处理事件以及支持早于 COMMAND_PRIORITY_BEFORE_* 可用的遗留代码。

现代 lexical 应用通常只需要 COMMAND_PRIORITY_EDITOR 优先级，因为最后注册先调用的顺序适合几乎所有用例。没有 BEFORE 的旧优先级可以被视为遗留，主要为兼容性提供。

以下是优先级的完整排序，从最低到最高：

  • COMMAND_PRIORITY_EDITOR
  • COMMAND_PRIORITY_BEFORE_EDITOR
  • COMMAND_PRIORITY_LOW
  • COMMAND_PRIORITY_BEFORE_LOW
  • COMMAND_PRIORITY_NORMAL
  • COMMAND_PRIORITY_BEFORE_NORMAL
  • COMMAND_PRIORITY_HIGH
  • COMMAND_PRIORITY_BEFORE_HIGH
  • COMMAND_PRIORITY_CRITICAL
