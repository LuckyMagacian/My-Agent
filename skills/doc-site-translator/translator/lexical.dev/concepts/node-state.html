NodeState

在 v0.26.0 中引入的 NodeState API 允许以参与协调、历史和 JSON 序列化的方式向任何节点临时添加任意状态。

Use Case #

NodeState 允许您的应用程序定义可以存储在任何节点上的键，并自动支持 JSON，您甚至可以向根节点添加状态以存储文档级元数据。

💡 提示

您甚至可以向 RootNode 添加节点状态以存储文档级元数据，这在以前是完全不可能的！

结合 NodeState 和其他 API（如 Listeners 或 Transforms），您可能无需进行太多 Node Customization 就能塑造编辑器以满足您的需求。

即使在子类化节点时，使用 NodeState 而不是额外属性来存储节点数据可能更高效，并且可以避免在构造函数、updateFromJSON 和 exportJSON 中编写大量样板代码。

Usage #

createState #

createState 创建一个 StateConfig，定义您的 NodeState 值的键和配置。键必须是本地唯一的，如果要在同一节点上使用，两个不同的 StateConfig 不能有相同的字符串键。

典型用法如下所示：

const questionState = createState('question', {
  parse: (v) => (typeof v === 'string' ? v : ''),
});

必需的 parse 函数有两个目的：

  • 它提供了一种类型安全和运行时安全的方式来解析序列化为 JSON 的值
  • 当用 undefined（或任何无效值）调用时，它应返回某个默认值（可能是 undefined 或 null 或您选择的任何其他值）

在这种情况下，问题必须是字符串，默认值为空字符串。

💡 提示

我们建议为您使用的数据类型构建小型可重用解析函数库，或者使用可以生成它们的库，如 zod、ArkType、Effect、Valibot 等，特别是在处理非原始数据类型时。

$getState #

$getState 从给定节点获取 NodeState 值，如果该键从未在节点上设置，则返回默认值。

const question = $getState(pollNode, questionState);

另请参阅 $getStateChange，如果您需要一种高效的方法来确定同一节点的两个版本上的状态是否已更改（通常用于 updateDOM，但在更新监听器或变更监听器中可能有用）。

$setState #

$setState 在给定节点上设置 NodeState 值。

const question = $setState(
  pollNode,
  questionState,
  'Are you planning to use NodeState?',
);
💡 提示

最后一个参数是 ValueOrUpdater，就像 React 的 useState setter。如果您使用更新器函数且值没有更改，节点及其 NodeState 不会被标记为脏。

Serialization #

节点的 NodeState（如果有任何值设置为非默认值）会被序列化为 NODE_STATE_KEY（等于 "$"）下的记录。

{
  "type": "poll",
  "$": {
    "question": "Are you planning to use NodeState?"
  }
}

Efficiency #

NodeState 使用写时复制方案来管理每个节点的状态。如果没有任何状态更改，则 NodeState 实例将在该节点的多个版本之间共享。

ℹ️ 信息

在给定的协调周期中，第一次通过 getWritable() 将 Lexical 节点标记为脏时，将创建该节点的新实例。前一版本的所有属性都设置在新实例上。NodeState 作为单个属性存储，在 NodeState 本身被标记为可写之前，不会进行内部状态的复制。

序列化为 JSON 时，只有当值不等于默认值时，每个键才会被存储。这可以节省大量空间和带宽。

Capabilities #

当前：

  • 允许您定义并向任何节点添加状态
  • 自动在节点的 JSON 中序列化该状态，支持版本控制和复制+粘贴
  • 与协调器一起工作，具有不同状态的 TextNodes 不会被隐式合并
  • @lexical/yjs 支持，NodeState 将像任何其他属性一样自动同步

未来：

  • 尚不支持与 Yjs 的直接集成，例如您不能将 Y.Map 存储为 NodeState 值
