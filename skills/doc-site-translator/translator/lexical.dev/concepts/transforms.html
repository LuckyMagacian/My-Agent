Node Transforms

Transforms 是响应 EditorState 更改的最有效机制。

例如：

  • 用户输入一个字符，如果单词现在等于 "congrats"，您想要将单词变成蓝色。
  • 我们程序化地向编辑器添加一个 MentionNode，MentionNode 立即在另一个 MentionNode 旁边（nodeA nodeB）。由于我们认为这使提及难以阅读，我们想要销毁/替换两个提及并将它们渲染为普通 TextNode。
const removeTransform = editor.registerNodeTransform(TextNode, (textNode) => {
  if (textNode.getTextContent() === 'blue') {
    textNode.setTextContent('green');
  }
});

Syntax #

Lifecycle #

Transforms 在更改传播到 DOM 之前按顺序执行，多个 transforms 仍然只导致单个 DOM 协调（Lexical 生命周期中最昂贵的操作）。

⚠️ 警告

虽然可以通过 update listener 后跟 update 来实现相同或非常相似的结果，但这强烈不建议，因为它会触发额外的渲染（最昂贵的生命周期操作）。此外，每个周期创建一个全新的 EditorState 对象，如果处理不当可能会干扰像 HistoryPlugin（undo-redo）这样的插件。

Dirty Nodes #

Dirty Leaves（任何不是 ElementNode 的 LexicalNode）和 Dirty Elements 分开跟踪以支持 transform 启发式方法。

内部上，脏节点有两种状态：

  • Intentionally Dirty 节点（叶或元素）调用了 getWritable() 或 markDirty()（别名）。维护 lexical 文档的双向链表树结构要求此 Intentionally Dirty 状态传播到直接兄弟，在某些情况下传播到父节点。
  • Unintentionally Dirty Element 节点是脏节点的祖先，没有被显式标记为 Intentionally Dirty。只有元素可以是 Unintentionally Dirty，因为叶节点根据定义不能有子节点。

协调器从 RootNode 开始工作（它是任何附着节点的祖先，因此每当任何附着节点脏时总是脏的）。Intentionally Dirty 节点调用其 createDOM 和/或 updateDOM。Dirty Elements 协调其所有子节点。因此，协调在没有脏节点的子树中的最高节点停止（除非它以标志运行以进行完全协调，将所有节点视为 Intentionally Dirty）。

ℹ️ 信息

transform 启发式方法依赖这些内部实现细节来找到不再需要 transforms 的固定点。

Transform heuristic #

  1. 我们首先转换叶节点。如果 transforms 生成额外的脏节点，我们重复步骤 1 和 2。这背后的原因是标记叶节点为脏也会将其所有父元素标记为脏。
  2. 我们转换元素。如果元素 transforms 生成额外的脏节点，我们重复步骤 1 和 2。如果元素 transforms 只生成额外的脏元素，我们只重复步骤 2。

节点在对其、其子节点或兄弟节点进行任何（或大多数）修改时将被标记为脏。

Preconditions #

Preconditions 对于防止 transforms 多次运行并最终导致无限循环至关重要。

Transforms 设计为在节点被修改（即 Intentionally Dirty）时运行。大多数情况下，transforms 只需要在更新后运行一次，但 transforms 的顺序性质可能产生顺序偏差。因此，transforms 反复运行，直到此特定类型的节点不再被任何 transforms 标记为 intentionally dirty。

因此，我们必须确保 transforms 不必要地将节点标记为脏。

// When a TextNode changes (marked as dirty) make it bold
editor.registerNodeTransform(TextNode, textNode => {
  // Important: Check current format state
  if (!textNode.hasFormat('bold')) {
    textNode.toggleFormat('bold');
  }
});

但很多时候，顺序不重要。下面的内容总是会以两个 transforms 的结果结束：

// Plugin 1
editor.registerNodeTransform(TextNode, textNode => {
  // This transform runs twice but does nothing the first time because it doesn't meet the preconditions
  if (textNode.getTextContent() === 'modified') {
    textNode.setTextContent('re-modified');
  }
})

// Plugin 2
editor.registerNodeTransform(TextNode, textNode => {
  // This transform runs only once
  if (textNode.getTextContent() === 'original') {
    textNode.setTextContent('modified');
  }
})

// App
editor.addListener('update', ({editorState}) => {
  const text = editorState.read($textContent);
  // text === 're-modified'
});
ℹ️ 信息

transform 启发式方法认为 RootNode 在任何节点脏时是 Intentionally Dirty，并确保此 transform 在所有其他 transforms 之后最后应用。这样，您可以将其视为"预更新" listener，在任何 DOM 协调发生之前发生。像任何其他 transform 一样，它可能在给定更新中被调用多次（特别是如果您的 RootNode transform 使任何节点脏）。

Transforms on parent nodes #

Transforms 对特定类型的节点非常具体。这适用于声明（registerNodeTransform Klass）和它在更新周期中触发的时间。

// Won't trigger
editor.registerNodeTransform(ParagraphNode, ..)

// Will trigger as TextNode was marked dirty
editor.registerNodeTransform(TextNode, ..)

editor.update(() => {
  const textNode = $getNodeByKey('3');
  textNode.setTextContent('foo');
});
