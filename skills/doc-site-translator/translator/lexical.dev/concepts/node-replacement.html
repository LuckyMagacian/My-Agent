Node Replacement

Node Replacement 允许您将编辑器中给定节点的所有实例替换为子类的实例。

Use Case #

📝 注意

在本文档的早期版本中，"Node Replacement" 被称为 "Node Overrides"。我们更改了名称以匹配实现中使用的术语。

💡 提示

如果您的用例只需要向现有节点添加临时数据，您可以使用 NodeState API 而不是子类化和节点替换。

一些最常用的 Lexical Nodes 由核心库拥有和维护。例如，ParagraphNode、HeadingNode、QuoteNode、List(Item)Node 等 - 这些都由 Lexical 包提供，这为某些编辑器功能提供了更简单的开箱即用体验，但也使得难以覆盖其行为。例如，如果您想更改 ListNode 的行为，通常会扩展该类并覆盖方法。但是，您如何告诉 Lexical 在 ListPlugin 中使用您的 ListNode 子类而不是使用核心 ListNode？这就是 Node Replacement 可以帮助的地方。

Node Replacement 允许您将编辑器中给定节点的所有实例替换为不同节点类的实例。这可以通过 Editor config 中的 nodes 数组完成：

const editorConfig = {
    ...
    nodes=[
        // Don't forget to register your custom node separately!
        CustomParagraphNode,
        {
            replace: ParagraphNode,
            with: (node: ParagraphNode) => {
                return $createCustomParagraphNode();
            },
            withKlass: CustomParagraphNode,
        }
    ]
}

在上面的代码片段中：

  • replace：指定要被替换的核心节点类型。
  • with：定义一个转换函数，将原始节点的实例替换为自定义节点。
  • withKlass：此选项确保与原始节点类型关联的行为与替换无缝协作。例如，当指定 withKlass 时，针对 ParagraphNode 的 node transforms 或 mutation listeners 也将应用于 CustomParagraphNode。如果没有此选项，自定义节点可能无法完全与编辑器的内置功能集成，导致意外行为。

一旦完成此操作，Lexical 将把所有 ParagraphNode 实例替换为 CustomParagraphNode 实例。此功能的一个重要用例是覆盖核心节点的序列化行为。请查看下面的完整示例。
