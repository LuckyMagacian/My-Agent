Lexical 中的同步机制

Lexical 的同步机制主要涉及以下几个层面：

状态同步

Lexical 使用 双缓冲（double-buffering） 技术管理 Editor State：

  • 当前状态：冻结的、不可变的 Editor State，表示已协调到 DOM 的内容
  • 待处理状态：正在进行的 Editor State，表示下一次协调的未来更改

当调用 editor.update() 时，当前状态被克隆作为起点，修改完成后形成新的不可变状态。 详细内容请参考 Editor State 文档。

DOM Reconciliation（DOM 协调）

DOM 协调是一个异步过程，Lexical 会将多个同步的 Editor State 更新批量合并到单个 DOM 更新中， 以提高性能。协调过程会对比"当前"和"待处理"两个 Editor State，只更新需要更改的 DOM 部分。

如果需要强制立即提交更新（例如在服务器上下文中操作编辑器状态），可以使用 discrete 选项： 

editor.update(() => {
  // manipulate the state...
}, {discrete: true});

协作同步

Lexical 支持实时协作编辑，通过 @lexical/collaboration 包与 Yjs 集成。 协作同步使用 COLLABORATION_TAG 和 SKIP_COLLAB_TAG 来控制同步行为。

详细内容请参考 Collaboration (React) 文档。

Update Tags

Update Tags 是控制同步行为的重要机制。以下是与同步相关的常用 Tags：

  • COLLABORATION_TAG - 表示 update 与协作编辑相关
  • SKIP_COLLAB_TAG - 表示 update 应跳过协作同步
  • SKIP_DOM_SELECTION_TAG - 防止更新 DOM selection
  • SKIP_SCROLL_INTO_VIEW_TAG - 防止将 selection 滚动到视图中

详细内容请参考 Updates 文档。
