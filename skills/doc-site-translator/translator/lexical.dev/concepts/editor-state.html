Editor State

为什么需要它？ #

在 Lexical 中，真相来源不是 DOM，而是 Lexical 维护并与编辑器实例关联的底层状态模型。

虽然 HTML 非常适合存储富文本内容，但在文本编辑方面往往"过于灵活"。例如，以下几行内容会产生相同的结果：

<i><b>Lexical</b></i>
<i><b>Lex</b><b>ical</b></i>
<b><i>Lexical</i></b>

当然，有方法可以将所有这些变体规范化为单一的规范形式，但这需要 DOM 操作，因此需要重新渲染内容。为了克服这个问题，我们可以使用 Virtual DOM 或 State。

除此之外，它还允许将内容结构与内容格式解耦。让我们看看这个存储在 HTML 中的例子：

<p>Why did the JavaScript developer go to the bar? <b>Because he couldn't handle his <i>Promise</i>s</b></p>

相比之下，Lexical 通过将格式信息偏移到属性中，将结构与格式解耦。这使我们能够拥有规范的文档结构，无论应用不同样式的顺序如何。

理解 Editor State #

您可以通过调用 editor.getEditorState() 从编辑器获取最新的编辑器状态。

编辑器状态有两个阶段：

  • 在更新期间，它们可以被视为"可变的"。请参阅下面的"更新状态"以了解如何修改编辑器状态。
  • 更新完成后，编辑器状态会被锁定并从此被视为不可变的。因此，这个编辑器状态可以被视为一个"快照"。

编辑器状态包含两个核心内容：

  • 编辑器节点树（从根节点开始）。
  • 编辑器选区（可以为 null）。

编辑器状态可以序列化为 JSON，编辑器实例提供了一个有用的方法来反序列化字符串化的编辑器状态。

以下是如何使用某些状态初始化编辑器然后持久化它的示例：

// Get editor initial state (e.g. loaded from backend)
const loadContent = async () => {
  // 'empty' editor
  const value = '{"root":{"children":[{"children":[],"direction":null,"format":"","indent":0,"type":"paragraph","version":1}],"direction":null,"format":"","indent":0,"type":"root","version":1}}';

  return value;
}

const initialEditorState = await loadContent();
const editor = createEditor(...);
registerRichText(editor, initialEditorState);

...

// Handler to store content (e.g. when user submits a form)
const onSubmit = () => {
  await saveContent(JSON.stringify(editor.getEditorState()));
}

对于 React，可能是这样的：

const initialEditorState = await loadContent();
const editorStateRef = useRef(undefined);

<LexicalComposer initialConfig={{
  editorState: initialEditorState
}}>
  <LexicalRichTextPlugin />
  <LexicalOnChangePlugin onChange={(editorState) => {
    editorStateRef.current = editorState;
  }} />
  <Button label="Save" onPress={() => {
    if (editorStateRef.current) {
      saveContent(JSON.stringify(editorStateRef.current))
    }
  }} />
</LexicalComposer>

Lexical 只在编辑器创建时读取 initialConfig.editorState 一次；稍后传递不同的值不会反映出来。请参阅下面的"更新状态"了解在初始化后更改编辑器状态的正确方法。

editorState 字段接受：

  • 一个 JSON 字符串，使用 editor.parseEditorState() 解析（如上面的示例）；
  • 一个 EditorState 实例，使用 editor.setEditorState() 直接应用；
  • 一个函数 (editor) => void，在 editor.update(...) 内部运行，仅当根节点仍然为空时调用（因此已填充的根节点保持不变）；
  • null，完全跳过默认初始化。与 collaboration plugin 一起使用，以便 Yjs 文档（而非 Lexical）拥有初始状态。

省略该字段（或传递 undefined）会使用默认的空 ParagraphNode 填充根节点。这两者不可互换：null 使根节点没有子节点，而 undefined 生成单个空行。如果您的 loadContent 可能为新文档返回 null 或 undefined，请合并为 undefined（例如 (await loadContent()) ?? undefined），这样编辑器仍然会获得默认段落，而不是协作风格未初始化状态。

更新状态 #

💡 提示

要深入了解状态更新的工作原理，请查看 Lexical 贡献者 @DaniGuardiola 的 这篇博客文章。

更新编辑器最常见的方法是使用 editor.update()。调用此函数需要传入一个函数，该函数将提供对底层编辑器状态进行修改的访问权限。当开始一个新的更新时，当前编辑器状态会被克隆并用作起点。从技术角度来看，这意味着 Lexical 在更新期间利用了一种称为双缓冲（double-buffering）的技术。有一个"当前"冻结的编辑器状态来表示最近一次协调到 DOM 的内容，还有另一个进行中的"待处理"编辑器状态，表示下一次协调的未来更改。

协调更新通常是一个异步过程，允许 Lexical 将多个同步的编辑器状态更新批量合并到单个 DOM 更新中——从而提高性能。当 Lexical 准备将更新提交到 DOM 时，更新批次中的底层修改和更改将形成一个新的不可变编辑器状态。调用 editor.getEditorState() 将返回基于更新更改的最新编辑器状态。

以下是如何更新编辑器实例的示例：

import {$getRoot, $getSelection} from 'lexical';
import {$createParagraphNode} from 'lexical';

// Inside the `editor.update` you can use special $ prefixed helper functions.
// These functions cannot be used outside the closure, and will error if you try.
// (If you're familiar with React, you can imagine these to be a bit like using a hook
// outside of a React function component).
editor.update(() => {
  // Get the RootNode from the EditorState
  const root = $getRoot();

  // Get the selection from the EditorState
  const selection = $getSelection();

  // Create a new ParagraphNode
  const paragraphNode = $createParagraphNode();

  // Create a new TextNode
  const textNode = $createTextNode('Hello world');

  // Append the text node to the paragraph
  paragraphNode.append(textNode);

  // Finally, append the paragraph to the root
  root.append(paragraphNode);
});

另一种设置状态的方法是 setEditorState，它用作为参数传递的状态替换当前状态。

以下是如何从字符串化的 JSON 设置编辑器状态的示例：

const editorState = editor.parseEditorState(editorStateJSONString);
editor.setEditorState(editorState);
⚠️ 警告

当使用满足 editorState.isEmpty() 的 EditorState 调用时，setEditorState 会抛出异常——即根节点是唯一的节点且没有选区。消息是 "setEditorState: the editor state is empty. Ensure the editor state's root node never becomes empty."。通过 editorState: null 初始化且从未追加内容（典型于协作文档在同伴连接之前）产生的 EditorState 正是这种形状，因此持久化和重新加载这种状态将在 setEditorState 调用时失败。请注意，parseEditorState 本身会成功——异常发生在应用步骤。要么在调用 setEditorState 之前用 editorState.isEmpty() 进行保护，要么在序列化之前用 ParagraphNode 填充文档。

状态更新监听器 #

如果您想知道编辑器何时更新以便对更改做出反应，可以向编辑器添加更新监听器，如下所示：

editor.registerUpdateListener(({editorState}) => {
  // The latest EditorState can be found as `editorState`.
  // To read the contents of the EditorState, use the following API:

  editorState.read(() => {
    // Just like editor.update(), .read() expects a closure where you can use
    // the $ prefixed helper functions.
  });
});

Listeners、Transforms 和 Commands 何时被调用？ #

有几种类型的回调可以注册到编辑器，它们与 Editor State 的更新相关。

回调类型 何时被调用
Update Listener 协调后
Mutation Listener 协调后
Node Transform 在 editor.update() 期间，回调完成后，如果注册的节点类型的任何实例被更新
Command 命令被派发到编辑器时立即调用（从隐式的 editor.update() 中调用）

使用离散更新进行同步协调 #

虽然提交调度和批处理通常是我们想要的，但有时它们会成为障碍。

考虑这个例子：您试图在服务器上下文中操作编辑器状态，然后将其持久化到数据库中。

editor.update(() => {
  // manipulate the state...
});

saveToDatabase(editor.getEditorState().toJSON());

这段代码不会按预期工作，因为 saveToDatabase 调用将在状态提交之前发生。保存的状态将是更新之前存在的状态。

幸运的是，LexicalEditor.update 的 discrete 选项强制立即提交更新。

editor.update(() => {
  // manipulate the state...
}, {discrete: true});

saveToDatabase(editor.getEditorState().toJSON());

克隆状态 #

Lexical 状态可以被克隆，可以选择带有自定义选区。您可能想要这样做的一个场景是设置编辑器的状态但不强制任何选区：

// Passing `null` as a selection value to prevent focusing the editor
editor.setEditorState(editorState.clone(null));
