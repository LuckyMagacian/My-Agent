Introduction

Lexical 是一个可扩展的 JavaScript web 文本编辑器框架，强调可靠性、可访问性和性能。Lexical 旨在提供一流的开发者体验，让您可以轻松地原型设计和构建功能，充满信心。结合高度可扩展的架构，Lexical 允许开发者创建独特的文本编辑体验，这些体验可以在规模和功能上增长。

Lexical 通过将自己附加到 contentEditable 元素来工作，从那里您可以使用 Lexical 的声明式 API 来实现功能，而无需担心 DOM 的特定边缘情况。事实上，在大多数情况下，您很少需要与 DOM 交互（除非您构建自己的自定义节点）。

Lexical 的核心包文件大小仅为 22kb（min+gzip），您只需为所需的功能付费。因此，Lexical 可以随着您的使用范围和需求增长。此外，在支持懒加载的框架中，您可以将 Lexical plugins 延迟到用户实际与编辑器交互时才加载——这可以大大帮助提高性能。

可以用 Lexical 构建什么？ #

Lexical 使创建复杂的文本编辑体验成为可能，这些体验如果使用内置的浏览器工具将非常复杂。我们构建 Lexical 是为了让开发者能够快速行动，并创建不同类型的文本体验，这些体验可以根据特定需求进行扩展。以下是您可以用 Lexical 做的一些（但不是全部）示例：

  • 简单的纯文本编辑器，但有比 <textarea> 更多的需求，例如需要 mentions、自定义 emojis、links 和 hashtags 等功能。
  • 更复杂的富文本编辑器，可用于在博客、社交媒体、消息应用程序上发布内容。
  • 完整的所见即所得（WYSIWYG）编辑器，可用于 CMS 或富内容编辑器。
  • 实时协作文本编辑体验，结合上述许多功能。

您可以将 Lexical 视为文本编辑器 UI 框架。虽然 Lexical 目前仅可在 web 上使用，但团队也在实验为其他平台构建 Lexical 的原生版本。在 Meta，Lexical 每天为 Facebook、Workplace、Messenger、WhatsApp 和 Instagram 上数亿用户的 web 文本编辑体验提供支持。

Lexical 的设计 #

Lexical 的核心是一个无依赖的文本编辑器框架，允许开发者构建强大、简单和复杂的编辑器界面。Lexical 有几个值得探索的概念：

Editor instances #

Editor instances 是将所有内容连接起来的核心。您可以将 contenteditable DOM 元素附加到 Editor instances，还可以注册 listeners 和 commands。最重要的是，Editor 允许更新其 EditorState。您可以使用 createEditor() API 创建 Editor instance，但在使用框架绑定（如 @lexical/react）时，通常不需要担心这一点，因为这已为您处理好了。

Editor States #

Editor State 是表示您想在 DOM 上显示内容的底层数据模型。Editor States 包含两部分：

  • 一个 Lexical Node Tree
  • 一个 Lexical Selection object

Editor States 创建后是不可变的，要更新它，必须通过 editor.update(() => {...}) 进行。但是，您也可以使用 node transforms 或 command handlers "hook" 到现有更新中——这些作为现有更新工作流的一部分被调用，以防止更新的级联/瀑布效应。您可以使用 editor.getEditorState() 获取当前的 Editor State。

Editor States 也可以完全序列化为 JSON，并且可以使用 editor.parseEditorState() 轻松序列化回编辑器。

读取和更新 Editor State #

当您想要读取和/或更新 Lexical node tree 时，必须通过 editor.update(() => {...}) 进行。您也可以通过 editor.read(mode, () => {...}) 或 editor.getEditorState().read(() => {...}) 对 Editor State 进行只读操作。传递给 update 或 read 调用的闭包很重要，必须是同步的。它是您拥有活动 Editor State 的完整"lexical"上下文的唯一地方，并为您提供对 Editor State node tree 的访问。我们提倡使用 $ 前缀函数（如 $getRoot()）的约定，以表示这些函数必须在此上下文中调用。尝试在 read 或 update 之外使用它们将触发运行时错误。

对于熟悉 React Hooks 的人来说，可以将这些 $functions 视为具有类似的功能：

功能 React Hooks Lexical $functions
命名约定 useFunction $function
需要上下文 只能在渲染时调用 只能在 update 或 read 中调用
可组合 Hooks 可以调用其他 hooks $functions 可以调用其他 $functions
必须同步 ✅ ✅
其他规则 ❌ 必须以相同顺序无条件调用 ✅ 无

Node Transforms 和 Command Listeners 是在隐式的 editor.update(() => {...}) 上下文中调用的。

允许进行嵌套 updates 或嵌套 reads，但 updates 绝不应嵌套在 reads 中。

嵌套 updates 非常强烈不建议使用，因为它们以一种非常不直观的延迟方式执行。当嵌套 update 被调度时，它会立即返回且没有任何效果，然后在父 update 返回后的某个时间执行。

Reads 可以嵌套，并且可以在 update 内部调用（例如读取节点的先前版本），但您不应在 update 内部调用 editor.read(...) 或 editor.read('force-commit', ...)，因为它会立即刷新 update，该 update 中的任何额外代码可能会抛出错误。

所有 Lexical Nodes 都依赖于关联的 Editor State。除了少数例外，您应该只在 read 或 update 调用中调用 Lexical Node 的方法和访问属性（就像 $ 函数一样）。Lexical Nodes 上的方法将首先尝试使用节点的唯一 key 从活动 Editor State 定位最新（可能是可写）版本的节点。逻辑节点的所有版本都具有相同的 key。这些 key 由 Editor 管理，仅在运行时存在（不序列化），应被视为随机且不透明的（不要编写假设 key 具有硬编码值的测试）。

这样做是因为 Editor State 的 node tree 在协调后会递归冻结，以支持高效的时间旅行（undo/redo 和类似用例）。更新节点的方法首先调用 node.getWritable()，它将创建冻结节点的可写克隆。这通常意味着任何现有引用（如局部变量）将引用节点的过时版本，但让 Lexical Nodes 总是引用 Editor State 可以实现更简单且更不易出错的数据模型。

💡 提示

如果您使用 editor.read(() => { /* callback */ }) 或 editor.read('force-commit', () => { /* callback */ })，它将首先刷新任何待处理的 updates，因此您将始终看到一致的状态。当您在 editor.update 或 editor.read('pending', ...) 中时，您将始终使用待处理状态工作，其中 node transforms 和 DOM reconciliation 可能尚未运行。editor.read('latest', ...) 或 editor.getEditorState().read() 将使用最新协调的 EditorState（在任何 node transforms、DOM reconciliation 等已经运行之后），任何待处理的 editor.update mutations 将尚未可见。

DOM Reconciler #

Lexical 有自己的 DOM reconciler，它接受一组 Editor States（总是"当前"和"待处理"），并对它们应用"diff"。然后它使用这个 diff 来只更新需要更改的 DOM 部分。您可以将其视为一种 virtual DOM，但 Lexical 能够跳过大部分 diffing 工作，因为它知道在给定更新中发生了什么变更。DOM reconciler 采用性能优化，有利于 content editable 的典型启发式方法——并能够自动确保 LTR 和 RTL 语言的一致性。

Listeners、Node Transforms 和 Commands #

除了调用 updates 之外，Lexical 的大部分工作是通过 listeners、node transforms 和 commands 完成的。这些都源于 Editor，并以 register 为前缀。另一个重要特性是所有 register 方法都返回一个函数来轻松取消订阅。例如，以下是如何监听 Lexical editor 的 update：

const unregisterListener = editor.registerUpdateListener(({editorState}) => {
  // An update has occurred!
  console.log(editorState);
});

// Ensure we remove the listener later!
unregisterListener();

Commands 是 Lexical 中用于将所有内容连接在一起的通信系统。可以使用 createCommand() 创建自定义 commands，并使用 editor.dispatchCommand(command, payload) 将其派发到 Editor。Lexical 在触发按键和其他重要信号发生时内部派发 commands。Commands 也可以使用 editor.registerCommand(command, handler, priority) 处理，传入的 commands 按优先级通过所有 handlers 传播，直到 handler 停止传播（类似于浏览器中的事件传播）。
