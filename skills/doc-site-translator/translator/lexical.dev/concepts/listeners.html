Listeners

Listeners 是一种机制，让 Editor 实例在发生特定操作时通知用户。所有 listeners 都遵循响应式模式，您可以在将来发生某事时执行操作。所有 listeners 也返回一个函数，可以轻松取消注册 listener。以下是 Lexical 当前支持的不同 listeners：

Update Listener #

当 Lexical 将更新提交到 DOM 时收到通知。

const removeUpdateListener = editor.registerUpdateListener(({editorState}) => {
  // The latest EditorState can be found as `editorState`.
  // To read the contents of the EditorState, use the following API:
  editorState.read(() => {
    // Just like editor.update(), .read() expects a closure where you can use
    // the $ prefixed helper functions.
  });
});

// Do not forget to unregister the listener when no longer needed!
removeUpdateListener();

update listener 回调接收一个包含以下属性的单个参数：

  • editorState - 最新更新的 Editor State
  • prevEditorState - 之前的 Editor State
  • updateTags - 传递给更新的所有标签的 Set

需要注意的一点是"瀑布式"更新。这是您可能在 update listener 内部调度更新，如下所示：

editor.registerUpdateListener(({editorState}) => {
  // Read the editorState and maybe get some value.
  editorState.read(() => {
    // ...
  });
  // Then schedule another update.
  editor.update(() => {
    // ...
  });
});

这种模式的问题在于它意味着我们最终做了两次 DOM 更新，而我们可能可以在单个 DOM 更新中完成。这可能会影响性能，这在文本编辑器中很重要。为了避免这种情况，我们建议查看 Node Transforms，它允许您监听节点更改并在同一给定更新中转换它们，这意味着没有瀑布式！

Text Content Listener #

当 Lexical 将更新提交到 DOM 且编辑器的文本内容从编辑器的先前状态发生变化时收到通知。如果更新之间的文本内容相同，listeners 将不会收到通知。

const removeTextContentListener = editor.registerTextContentListener(
  (textContent) => {
    // The latest text content of the editor!
    console.log(textContent);
  },
);

// Do not forget to unregister the listener when no longer needed!
removeTextContentListener();

Mutation Listener #

当特定类型的 Lexical 节点发生变更时收到通知。变更有三种状态：

  • 'created'
  • 'destroyed'
  • 'updated'

Mutation listeners 非适合跟踪特定类型节点的生命周期。它们可用于处理与特定类型节点相关的外部 UI 状态和 UI 功能。

如果任何现有节点在 DOM 中，并且 skipInitialization 不为 true，listener 将立即被调用，updateTag 为 'registerMutationListener'，其中所有节点都有 'created' NodeMutation。这可以通过 skipInitialization 选项控制（其默认值以前为 true 以向后兼容 <=0.16.1，但在 0.21.0 中已更改为 false）。

const removeMutationListener = editor.registerMutationListener(
  MyCustomNode,
  (mutatedNodes, { updateTags, dirtyLeaves, prevEditorState }) => {
    // mutatedNodes is a Map where each key is the NodeKey, and the value is the state of mutation.
    for (let [nodeKey, mutation] of mutatedNodes) {
      console.log(nodeKey, mutation)
    }
  },
  {skipInitialization: false}
);

// Do not forget to unregister the listener when no longer needed!
removeMutationListener();

Editable Listener #

当编辑器的模式发生更改时收到通知。编辑器的模式可以通过 editor.setEditable() 更改。

const removeEditableListener = editor.registerEditableListener(
  (editable) => {
    // The editor's mode is passed in!
    console.log(editable);
  },
);

// Do not forget to unregister the listener when no longer needed!
removeEditableListener();

Decorator Listener #

当编辑器的 decorator 对象发生更改时收到通知。decorator 对象包含所有 DecoratorNode keys -> 其装饰值。这主要用于外部 UI 框架。

const removeDecoratorListener = editor.registerDecoratorListener(
  (decorators) => {
    // The editor's decorators object is passed in!
    console.log(decorators);
  },
);

// Do not forget to unregister the listener when no longer needed!
removeDecoratorListener();

Root Listener #

当编辑器的根 DOM 元素（Lexical 附着的 content editable）发生更改时收到通知。这主要用于将事件 listeners 附着到根元素。root listener 函数在注册时立即执行，然后在任何后续更新时执行。
