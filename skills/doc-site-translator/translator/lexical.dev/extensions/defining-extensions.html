定义扩展

扩展是一个符合 LexicalExtension 接口的普通 JavaScript 对象。defineExtension 函数只是一个恒等函数，用于方便 TypeScript 类型推断。它会被编译为以下代码，并且可能会被你的打包器或压缩器优化掉：

function defineExtension(extension) {
  return extension;
}

扩展必须是稳定的引用。最佳做法是在模块作用域中定义它们，但如果出于某种原因你必须在 React 组件内部定义扩展，你需要通过某种方式使其保持稳定，例如根据实际情况使用 useState、useMemo 或 useRef。

必需属性​

name​

扩展的唯一必需属性是 name。名称是一个字符串，应该在你的编辑器中对该扩展保持唯一。最佳实践是为你的项目或组织使用一个作用域，以确保可复用的扩展之间不会发生冲突。

在 Lexical 仓库中的一般做法是：当只导出一个扩展时，使用包名作为扩展名（例如 DragonExtension 的名称是 @lexical/dragon）；当导出多个扩展时，则额外添加路径（例如 AutoFocusExtension 的名称是 @lexical/extension/AutoFocus）。

InitialEditorConfig​

扩展可以指定编辑器的配置覆盖，这些配置由 InitialEditorConfig 接口定义。完整属性列表请参见 API 文档。这里的每个属性都有默认值。

合并属性​

对于设计为依赖项使用的扩展，指定需要合并的属性也很有用，例如 html（覆盖 HTML 导入/导出）、nodes（向编辑器注册新节点或节点覆盖）、或 theme（指定 Lexical 提供的节点所使用的类名）。

export const CodeExtension = defineExtension({
  name: '@lexical/code',
  nodes: () => [CodeNode, CodeHighlightNode],
});

根属性​

还有一些属性对于你提供给 buildEditorFromExtensions 或 LexicalExtensionComposer 的 extension 属性的"根"扩展更有用，在这里你可以指定那些只能有意义地设置一次的属性，例如 $initialEditorState、editable、onError、namespace 或 parentEditor。

这些属性没有要求必须从扩展层级的特定层级设置，也不要求必须设置，但每个编辑器只能有意义地设置一次。

const editor = buildEditorFromExtensions(
  defineExtension({
    name: "@example/basic-rich-text-editor",
    namespace: "basic-rich-text-editor",
    dependencies: [RichTextExtension],
    register: (editor: LexicalEditor) => {
      console.log("Editor Created");
      return () => console.log("Editor Disposed");
    },
  }),
);

扩展依赖​

Lexical Extension 有两种方式让扩展之间相互依赖并指定配置：

  • dependencies 是直接的（通过引用）
  • peerDependencies 是间接的（通过名称）且可选的

这个规则的例外是 peerDependencies，它们是可选依赖。

dependencies​

dependencies 属性是你的扩展所依赖的扩展引用数组。例如，如果你的扩展使用 React，那么它应该依赖于 ReactExtension。

依赖关系形成一个有向无环图。这意味着必须不能存在任何循环依赖。如果扩展 A 依赖于扩展 B，那么从 B 到 A（或从 A 到 A）必须不存在任何依赖路径。

这个数组可以包含扩展的直接引用，也可以包含对 configExtension 的调用。

export const ExampleExtension = defineExtension({
  name: "@example/extension",
  dependencies: [
    SomeExtension,
    configExtension(ReactExtension, {
      decorators: [<ExampleDecorator />]
    }),
  ],
});

peerDependencies​

peerDependencies 属性是通过名称指定的可选扩展数组。它们不是必需的要求，但在这里指定它们可以让你的扩展在运行时找到它们，并在它们随编辑器构建时覆盖它们的配置。你可以使用 declarePeerDependency 来构建这个具有类型推断的数组。

由于这些是可选的且通过名称指定，peerDependencies 之间的图结构不受限制，允许循环。

这在实践中很少需要，属于高级用例，通常用于避免直接导入或依赖循环。更多详情请参见 Peer Dependencies。

conflictsWith​

conflictsWith 属性是通过名称指定的已知与此扩展冲突的扩展数组。例如，在同一个编辑器中同时使用 RichTextExtension 和 PlainTextExtension 是没有意义的。

export const PlainTextExtension = defineExtension({
  conflictsWith: ['@lexical/rich-text'],
  dependencies: [DragonExtension],
  name: '@lexical/plain-text',
  register: registerPlainText,
});

这在实践中很少需要，属于高级用例，但在需要时可以提供有用的早期错误提示。

阶段​

使用扩展构建编辑器是通过顺序阶段完成的，以下属性是在特定点挂钩该过程的有用方式。

config​

config 是一个对象，作为你扩展的默认配置，该对象的属性可以被其他扩展通过 configExtension 或 declarePeerDependency 覆盖。

此对象在后续阶段用于构建 init 和/或 output。

config 阶段发生在编辑器构建之前。

mergeConfig​

mergeConfig 是一个函数，如果你需要比浅层对象合并更细粒度的控制（例如连接数组），可以用来合并配置与其覆盖值。例如：

interface StringArrayConfig {
  array: string[];
}
const StringArrayExtension = defineExtension({
  config: safeCast<StringArrayConfig>({array: []}),
  name: "@example/StringArray",
  mergeConfig(a, b) {
    const config = shallowMergeConfig(a, b);
    if (b.array) {
      config.array =
        b.array.length > 0
          ? [...a.array, ...b.array]
          : a.array;
    }
    return config;
  },
});

默认实现是 shallowMergeConfig，大多数扩展不需要覆盖它。

init​

init 阶段发生在编辑器构建之前，但在合并后的编辑器配置可用且所有扩展都已配置之后。它可以用来引用来自 peer 的配置、计算应该在 build 期间可用的数据，通常是在编辑器创建之前对任何扩展或编辑器配置进行变更的最后手段。

此函数的结果在后续阶段可用。

这在实践中很少需要，属于高级用例。

build​

build 阶段发生在编辑器构建之前，但在 config 和 init 之后。build 阶段的返回值是 output，在后续阶段可用。

output 通常是扩展向彼此以及应用中的节点提供功能的方式。一个非常常见的用例是使用 namedSignals 从配置构建信号，以便你的扩展的行为可以在运行时被修改（例如 disabled 是一个非常常见的用例）。

build 的 output 的其他用例包括提供共享数据结构、类型化的主题配置、扩展实现的命令的引用等。

export interface TabIndentationConfig {
  disabled: boolean;
  maxIndent: null | number;
}
export const TabIndentationExtension = defineExtension({
  build(editor, config, state) {
    return namedSignals(config);
  },
  config: safeCast<TabIndentationConfig>({disabled: false, maxIndent: null}),
  name: '@lexical/extension/TabIndentation',
  register(editor, config, state) {
    const {disabled, maxIndent} = state.getOutput();
    return effect(() => {
      if (!disabled.value) {
        return registerTabIndentation(editor, maxIndent);
      }
    });
  },
});

register​

这发生在编辑器构建完成之后。这是你注册扩展所需的任何命令、监听器等的地方。它可以通过 state.getInit() 和 state.getOutput() 分别使用 init 或 build 的结果。

返回值是一个销毁函数，通常是 mergeRegister 的结果。

afterRegistration​

这发生在每个扩展的 register 都被调用之后，此时所有命令都应该已注册。这是 InitialStateExtension 将 $initialEditorState 应用于编辑器的阶段，因此 editor.setRootElement 应该不早于此阶段调用（当然也可以在编辑器构建之后、扩展之外调用）。

返回值是一个销毁函数，通常是 mergeRegister 的结果。
