Signals

Lexical Extensions 使用 signals 作为响应式接口，你可以用它与扩展之间以及扩展内部进行通信。

动机​

在最底层，Lexical 各部分之间的通信是通过回调完成的，例如 registerCommand、registerUpdateListener、registerMutationListener 以及 DOM 的 addEventListener。

这些回调的行为以及在某些情况下是否注册，取决于扩展的本地状态，这些状态也可能是可变的，因此需要使用类似的回调机制进行 naïve 实现。对于传统的 React 插件，这个机制是 useEffect，它非常粗粒度，在使用其他框架或不使用框架时并没有真正可移植的等效方案。

最初的原型主要也是基于回调的，但当你需要基于多个回调或配置值的"结果"进行工作时，这很快变得非常难以处理。Signals 是解决这个问题的一个更通用的方案。甚至有一个 TC39 Signals Proposal 来将此基础设施添加到 JavaScript 标准中。

Signals 还可以通过 batch 等原语减少冗余回调来进行优化，或者通过 peek 检查当前值而不添加任何订阅。基本上，同一个 Signal 可以像 React State 一样使用（当你想要在值随时间变化时运行代码），也可以像 React Ref 一样使用（当你只需要知道当前值时，这在事件处理程序中很典型）。

Signals 还不需要你管理依赖数组或使用编译器，订阅和依赖是在运行时根据使用情况推断的。这意味着某个 effect 订阅的 signal 集合可以在不违反任何规则或不产生任何警告的情况下发生变化。

实现​

由于 Signals 尚未标准化，而且 signal-polyfill 还没有准备好用于生产环境，因此决定利用 @preact/signals-core。这个实现没有依赖、经过优化且测试充分。

为了未来的兼容性，我们不建议你直接使用 @preact/signals-core，而是使用从 @lexical/extension 重新导出的版本。

在初始发布时，这些重新导出包括：

export {
  batch,
  computed,
  effect,
  type ReadonlySignal,
  type Signal,
  signal,
  type SignalOptions,
  untracked,
} from '@preact/signals-core';

用法​

关于 signal 原语如何工作的详细示例，你可以阅读 Preact Signals 文档。

Lexical 提供以下高层 signal 函数来更容易地构建扩展：

namedSignals​

namedSignals 是一个便捷函数，用于从配置对象的每个属性输出独立的 signals。

export interface TabIndentationConfig {
  disabled: boolean;
  maxIndent: null | number;
}

export const TabIndentationExtension = defineExtension({
  build(editor, config, state) {
    return namedSignals(config);
  },
  config: safeCast<TabIndentationConfig>({disabled: false, maxIndent: null}),
  name: '@lexical/extension/TabIndentation',
  register(editor, config, state) {
    const {disabled, maxIndent} = state.getOutput();
    return effect(() => {
      if (!disabled.value) {
        // This register function's implementation uses peek on the maxIndent
        // signal to get its current value when needed, no need to re-register
        // every time this value changes.
        return registerTabIndentation(editor, maxIndent);
      }
    });
  },
});

watchedSignal​

watchedSignal 等同于 React 的 useSyncExternalStore

export const EditorStateExtension = defineExtension({
  build(editor, config, state) {
    return watchedSignal(
      () => editor.getEditorState(),
      (editorStateSignal) =>
        editor.registerUpdateListener((payload) => {
          editorStateSignal.value = payload.editorState;
        }),
    );
  },
  name: '@lexical/extension/EditorState',
});
