React 与 Lexical Extension

Lexical Extension 大幅改进了对非 React 用法的支持，但在支持 React 时并未做出任何妥协。

迁移到 LexicalExtensionComposer 的最小步骤​

将应用从 LexicalComposer 迁移到 LexicalExtensionComposer 非常简单，但有两点需要注意。

将 initialConfig 转换为 extension​

迁移前：

const initialConfig = {
  namespace: 'MyEditor',
  nodes: [QuoteNode, HeadingNode],
  theme,
  editorState(editor) {
    editor.update($initialEditorState, {tag: HISTORY_MERGE_TAG});
  },
  // This is the default when using Lexical Extension
  onError(err) {
    throw err;
  },
};

迁移后：

// 请确保这是一个稳定的引用，可以通过在模块顶层定义它，
// 或者使用类似 `useRef` 或 `useState` 的方式来创建它。
// 每当此对象发生变化时，编辑器都会被重新创建。
const appExtension = defineExtension({
  name: 'MyEditor',
  namespace: 'MyEditor',
  nodes: () => [QuoteNode, HeadingNode],
  theme,
  $initialEditorState,
});

从 LexicalComposer 切换到 LexicalExtensionComposer​

迁移前：

<LexicalComposer initialConfig={initialConfig}>
    <RichTextPlugin
        contentEditable={<ContentEditable />}
        ErrorBoundary={LexicalErrorBoundary}
    />
    {/* other legacy React plugins */}
</LexicalComposer>

迁移后：

<LexicalExtensionComposer extension={appExtension} contentEditable={null}>
    <RichTextPlugin
        contentEditable={<ContentEditable />}
        ErrorBoundary={LexicalErrorBoundary}
    />
    {/* other legacy React plugins */}
</LexicalExtensionComposer>

这是一个最小化的迁移，在大多数情况下，你可以将插件用法迁移到扩展依赖项。例如，使用 RichTextExtension 而不是 RichTextPlugin：

const appExtension = defineExtension({
  name: 'MyEditor',
  namespace: 'MyEditor',
  dependencies: [RichTextExtension],
  theme,
  $initialEditorState,
});
<LexicalExtensionComposer extension={appExtension}>
  {/* By default the contentEditable is the first child, defaulting to <ContentEditable /> */}
  {/* other legacy React plugins */}
</LexicalExtensionComposer>

React 插件（旧版）​

这些插件可以直接使用，只需将其作为 composer 的子组件渲染。你可能希望将它们打包为扩展以便更轻松地复用，或考虑重构它们以在没有 React 的情况下工作。参见 Extension Decorators、Output Components 和 React Independence，了解重新打包或重构旧版插件的策略。

Extension Decorators​

旧版 React 插件的一个常见用例是渲染某个 React 组件，但该组件在文档中的位置并不重要。这种情况包括：组件只是一个始终返回 null 的效果，或者渲染类似 portal 的内容。用户无需手动决定这些组件的渲染位置，因此 Lexical 的 ReactExtension 会维护一个数组来自动渲染这些组件。

// 这正是你编写旧版 React 插件的方式
function LogEditorPlugin() {
 const [editor] = useLexicalComposerContext()
 useEffect(() => {
   console.log(editor);
 }, [editor]);
 return null;
}
// 这是将插件声明为扩展的方式
// 该扩展依赖 React 并将此插件作为 decorator 渲染
export const LogEditorExtension = defineExtension({
 name: "@example/LogEditor",
 dependencies: [
   configExtension(ReactExtension, {
     decorators: [<LogEditorPlugin />]
   }),
 ],
});

Output Components​

在某些情况下，用户需要精确决定扩展的组件在 React 文档中的渲染位置，此时约定是提供一个 Output Component。

这里有一个 TreeViewExtension，它定义了一个 Output Component 来渲染具有指定配置的 TreeView。

export function TreeViewExtensionComponent(
  props: Partial<TreeViewConfig>,
): JSX.Element {
  const [editor] = useLexicalComposerContext();
  return (
    <TreeView
      editor={editor}
      {...useExtensionDependency(TreeViewExtension).config}
      {...props}
    />
  );
}

export const TreeViewExtension = defineExtension({
  build: () => ({Component: TreeViewExtensionComponent}),
  config,
  dependencies: [ReactExtension],
  name: '@lexical/react/TreeView',
});

可以通过 useExtensionComponent hook 或 ExtensionComponent 组件来获取此扩展组件。

return (
  <ExtensionComponent
    lexical:extension={TreeViewExtension}
    viewClassName="tree-view-output" />
);
const TreeViewComponent = useExtensionComponent(TreeViewExtension);
return (<TreeViewComponent viewClassName="tree-view-output" />);

React Independence​

许多旧版插件只是 useEffect 的包装器，这些通常根本不需要 React。例如：

迁移前：

export function CheckListPlugin(): null {
  const [editor] = useLexicalComposerContext();
  useEffect(() => {
    return registerCheckList(editor);
  }, [editor]);
  return null;
}

迁移后：

export const CheckListExtension = defineExtension({
  name: "@lexical/list/CheckList",
  register: registerCheckList,
});

不使用 JSX 调用 React 扩展和插件​

ReactPluginHostExtension 是一个允许你在应用的特定 DOM 元素上挂载 React root 的扩展，这样非原生 React 应用仍然可以利用现有的依赖 React 的旧版插件和扩展。

虽然这意味着你的应用将包含 React 运行时，但你不必在应用中使用 JSX 或任何其他 React 基础设施。

参见 extension-vanilla-react-plugin-host 了解此扩展及其 API 的用法
