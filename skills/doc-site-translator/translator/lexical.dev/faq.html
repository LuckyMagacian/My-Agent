FAQ

如何清空编辑器内容？ #

要清空 Lexical 编辑器的内容，请在 update callback 中调用 RootNode 的 clear() 方法：

import {$getRoot} from 'lexical';

editor.update(() => {
  const root = $getRoot();
  root.clear();
});

clone 方法应该直接使用吗？ #

clone 方法不应该直接使用。相反，应该优先使用 $copyNode() 或 getWritable() 来复制节点。

// 推荐
const writableNode = node.getWritable();
const copiedNode = $copyNode(node);

Reconciliation 什么时候发生？ #

Lexical 中的 reconciliation 使用 queueMicrotask 异步调度，确保来自单个逻辑事件的更新被批量处理。这比 setTimeout(..., 0) 提供了更高的即时性，比 Promise.resolve().then(...) 更少的开销。

如果需要强制同步 reconciliation，可以在 editor.update 中使用 'discrete' 选项：

editor.update(() => {
  // 更新操作...
}, { discrete: true });

read() 方法是如何工作的？ #

read() 方法对编辑器状态执行只读操作，提供对编辑器上下文的访问而不允许变更。在 read 操作开始之前，任何待处理的更新都会被刷新。

editor.read(() => {
  const root = $getRoot();
  // 只读操作...
});

如何控制编辑器的可编辑状态？ #

setEditable 方法允许您控制编辑器的可编辑状态。当设置为 false 时，编辑器将停止监听底层 contenteditable 元素上的用户事件。

// 设为只读
editor.setEditable(false);

// 恢复可编辑
editor.setEditable(true);

有哪些可用的监听器？ #

registerTextContentListener #

当 Lexical 将更新提交到 DOM 且编辑器的文本内容与之前状态相比发生变化时触发。如果文本内容在更新之间保持相同，则不会发送通知。返回一个清理函数以移除监听器。

const unregister = editor.registerTextContentListener((text) => {
  console.log('文本内容已更改:', text);
});

// 稍后清理
unregister();

registerEditableListener #

每当编辑器的可编辑状态发生变化时调用。监听器可以选择性地返回一个函数，该函数将在下一个状态转换或清理之前被调用。

editor.registerEditableListener((editable) => {
  console.log('编辑器可编辑状态:', editable);
});

registerDecoratorListener #

当编辑器的 decorator 对象发生变化时触发回调。这对于与外部 UI 框架集成非常有用，通过监视 DecoratorNode 键及其关联值的变化。

editor.registerDecoratorListener((decorators) => {
  // 更新 decorator 渲染...
});

registerRootListener #

注册一个监听器以监听编辑器根 DOM 元素的变化。这主要用于将事件监听器附加到根元素。监听器在注册时和后续更新时执行。如果监听器返回一个函数，该函数将在下一个转换或清理之前被调用。

editor.registerRootListener((nextRoot, prevRoot) => {
  if (prevRoot) {
    // 清理旧的监听器
  }
  if (nextRoot) {
    // 设置新的监听器
  }
});

LineBreakNode 是如何工作的？ #

LineBreakNode 表示编辑器中的换行符。其 createDOM 方法必须返回单个 HTMLElement，getTextContent 方法返回换行符。

transform() 方法是什么？ #

transform 方法是一个实验性功能，用于在编辑器初始化期间在节点上注册要执行的函数。通常建议使用 LexicalEditor.registerNodeTransform API 代替。

configExtension() 是如何工作的？ #

configExtension 函数允许覆盖 Extension 的部分配置。当将 extensions 用作其他 extensions 的依赖项或从 extensions 构建编辑器时，这非常有用。配置在编辑器构建之前使用 extension.mergeConfig 或 shallowMergeConfig 合并。

const myExtension = configExtension(BaseExtension, {
  // 覆盖配置选项
  someOption: 'new value',
});
