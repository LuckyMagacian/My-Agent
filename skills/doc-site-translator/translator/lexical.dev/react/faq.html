React FAQ

我的应用在 dev 模式下使用 StrictMode 时无法工作，怎么办？ #

当使用 React StrictMode 与 Lexical 时，请确保您的 React hooks 使用遵循 React 的约定。在 React 19 中，useMemo 调用在 StrictMode 重渲染之间被缓存。如果您的 useEffect 有副作用，请验证它们是否已经发生，并实现清理函数。

LexicalComposer 的 initialConfig 仅在第一次渲染时被考虑一次。优先使用像 useLexicalEditable 这样的 hooks，而不是手动注册 listeners，特别是当它们的来源是 effect 时，因为 listener 调用可能会受到 StrictMode 渲染行为的影响。

解决方案 #

  • 确保所有 effect 都有正确的清理函数
  • 不要依赖多次渲染之间的状态持久性
  • 使用 Lexical 提供的 hooks（如 useLexicalEditable）而不是手动注册
  • 验证副作用在执行前是否已经发生
💡 提示

StrictMode 会在开发模式下双重调用某些函数（包括 effects）以帮助发现副作用问题。这是预期行为，不应在生产环境中发生。

React Hooks 使用规则 #

Lexical 的 $ 前缀函数与 React Hooks 有类似的功能：

特性 React Hooks Lexical $函数
命名约定 useFunction $function
所需上下文 只能在渲染时调用 只能在 update 或 read 时调用
可组合 Hooks 可以调用其他 Hooks $函数可以调用其他 $函数
必须同步 ✅ ✅
其他规则 ❌ 必须以相同顺序无条件调用 ✅ 无此限制

如何在组件外部访问 Editor？ #

使用 EditorRefPlugin 可以在 LexicalComposer 外部访问 editor 实例。这对于需要在 React 树中位于 LexicalComposer 外部的按钮或其他 UI 组件非常有用，这些组件需要更新或读取 EditorState。

<LexicalComposer initialConfig={initialConfig}>
  <RichTextPlugin ... />
  <EditorRefPlugin
    editorRef={(instance) => {
      // 将 editor 实例存储到外部变量或 ref
      myEditorRef.current = instance;
    }}
  />
</LexicalComposer>

// 在其他组件中使用
function ExternalToolbar() {
  const handleClick = () => {
    myEditorRef.current?.dispatchCommand(FORMAT_TEXT_COMMAND, 'bold');
  };
  return <button onClick={handleClick}>Bold</button>;
}

如何延迟加载 Plugins？ #

Lexical React plugins 是 React 组件，这使得它们高度可组合。您可以使用 React 的 lazy 和 Suspense 延迟加载 plugins：

import {lazy, Suspense} from 'react';

const HeavyPlugin = lazy(() => import('./HeavyPlugin'));

function Editor() {
  return (
    <LexicalComposer initialConfig={initialConfig}>
      <RichTextPlugin ... />
      <Suspense fallback={null}>
        <HeavyPlugin />
      </Suspense>
    </LexicalComposer>
  );
}

如何避免不必要的重渲染？ #

当使用 Lexical 与 React 时，您可能会遇到不必要的重渲染问题。以下是一些优化策略：

  • 使用 useMemo 缓存传递给 plugins 的回调函数
  • 避免在每次渲染时创建新的配置对象
  • 使用 React.memo 包装频繁更新的组件
  • 考虑使用 useLexicalSubscription 进行细粒度订阅

如何处理嵌套的 LexicalComposer？ #

当使用嵌套编辑器时，可以使用 LexicalNestedComposer。注意 skipCollabChecks 属性：如果未显式设置为 true 且 collaboration plugin 处于活动状态，嵌套编辑器的子组件将不会渲染，直到 collaboration 准备就绪。

<LexicalNestedComposer
  initialConfig={nestedConfig}
  skipCollabChecks={true}  // 跳过协作准备检查
>
  <RichTextPlugin ... />
</LexicalNestedComposer>

如何在不使用 JSX 的情况下使用 React Extensions？ #

ReactPluginHostExtension 允许将 React root 挂载到特定的 DOM 元素，使未使用 React 构建的应用能够利用依赖 React 的 plugins 和 extensions。这种集成不需要在应用中使用 JSX 或其他 React 基础设施（尽管它包含 React runtime）。

import {ReactPluginHostExtension} from '@lexical/react/ReactPluginHostExtension';
import {mountReactPluginHost} from '@lexical/react/ReactPluginHostExtension';

// 挂载 React host
mountReactPluginHost(editor, container);

// 然后可以挂载 React components
mountReactPluginComponent(editor, {
  component: MyPlugin,
  props: {}
});
