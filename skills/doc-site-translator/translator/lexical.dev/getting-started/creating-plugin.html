创建 Plugin

本页面介绍 Lexical Plugin 的创建，独立于任何框架或库。对于还不熟悉 Lexical 的用户，建议先查看 Quick Start (Vanilla JS) 页面。

与许多其他框架不同，Lexical 没有为其 Plugin 定义任何特定的接口。Plugin 在最简单的形式下是一个接受 LexicalEditor 实例并返回清理函数的函数。通过访问 LexicalEditor，Plugin 可以通过 Commands、Transforms、Nodes 或其他 API 来扩展编辑器。

在本指南中，我们将创建一个 Plugin，它将表情符号（:)、:P 等）替换为实际的 emoji（使用 Node Transforms），并通过创建我们自己的自定义 Node（扩展 TextNode）来使用自己的图形进行 emoji 渲染。

前置条件 #

我们假设您已经实现了（参见提供的代码中的 findEmoji.ts）一个函数，该函数允许您在文本中查找 emoji 短代码（表情符号）并返回它们的位置以及其他信息：

// findEmoji.ts
export type EmojiMatch = Readonly<{position: number, shortcode: string, unifiedID: string}>;

export default function findEmoji(text: string): EmojiMatch | null;

创建自己的 LexicalNode #

Lexical 作为框架提供两种方式来自定义其内容的外观：

  • 通过扩展以下基础 Node 之一：
    • ElementNode – 用作其他 Node 的父级，可以是块级或内联。
    • TextNode – 包含文本的叶子类型 Node（因此不能有子元素）。
    • DecoratorNode – 用于在编辑器中插入任意视图（组件）。
  • 通过 Node Replacement – 如果您想增强内置 Node（如 ParagraphNode）的行为，这很有用。

在我们的例子中，我们不期望 EmojiNode 有任何子 Node，也不打算插入任意组件，因此最好的选择是继续扩展 TextNode。

export class EmojiNode extends TextNode {
  __unifiedID: string;

  static getType(): string {
    return 'emoji';
  }

  static clone(node: EmojiNode): EmojiNode {
    return new EmojiNode(node.__unifiedID, node.__key);
  }

  constructor(unifiedID: string, key?: NodeKey) {
    const unicodeEmoji = /*...*/;
    super(unicodeEmoji, key);

    this.__unifiedID = unifiedID.toLowerCase();
  }

  /**
  * DOM that will be rendered by browser within contenteditable
  * This is what Lexical renders
  */
  createDOM(_config: EditorConfig): HTMLElement {
    const dom = document.createElement('span');
    dom.className = 'emoji-node';
    dom.style.backgroundImage = `url('${BASE_EMOJI_URI}/${this.__unifiedID}.png')`;
    dom.innerText = this.__text;

    return dom;
  }

  static importJSON(serializedNode: SerializedEmojiNode): EmojiNode {
    return $createEmojiNode(serializedNode.unifiedID).updateFromJSON(serializedNode);
  }

  exportJSON(): SerializedEmojiNode {
    return {
      ...super.exportJSON(),
      unifiedID: this.__unifiedID,
    };
  }
}

上面的示例展示了扩展 TextNode 的自定义 Node 的绝对最小设置。让我们看看这里的关键要素：

  • constructor(...) + 类属性 – 允许我们在运行时在 Node 中存储自定义数据以及接受自定义参数。
  • getType() 和 clone(...) – 这些方法允许 Lexical 正确识别 Node 类型，以及能够正确克隆它，因为我们可能想要自定义克隆行为。
  • importJSON(...) 和 exportJSON() – 定义我们的数据如何序列化/反序列化到/从 Lexical 状态。在这里定义您的 Node 在状态中的表示。
  • createDOM(...) – 定义 Lexical 将渲染的 DOM。

创建 Node Transform #

Transforms 允许高效响应 EditorState 的变化，以及用户输入。它们的高效来自于 Transform 在 DOM 协调（Lexical 生命周期中最昂贵的操作）之前执行。

此外，值得一提的是 Lexical Node Transforms 足够智能，让您无需考虑在 Transform 中所做的修改的任何副作用或与其他 Transform 监听器的相互依赖关系。经验法则是，在特定 Transform 中对 Node 所做的更改将触发其他 Transform 的重新运行，直到 EditorState 不再发生变化。在 Transform heuristic 中了解更多信息。

在我们的示例中，我们有一个简单的 Transform，执行以下业务逻辑：

  1. 尝试转换 TextNode。它将在任何 TextNode 更改时运行。
  2. 检查 TextNode 中的文本是否包含 emoji 短代码（表情符号）。如果没有则跳过。
  3. 将 TextNode 拆分为 2 或 3 部分（取决于短代码在文本中的位置），以便目标 emoji 短代码拥有自己独立的 TextNode。
  4. 将 emoji 短代码 TextNode 替换为 EmojiNode。
import {LexicalEditor, TextNode} from 'lexical';


import {$createEmojiNode} from './EmojiNode';
import findEmoji from './findEmoji';


function textNodeTransform(node: TextNode): void {
  if (!node.isSimpleText() || node.hasFormat('code')) {
    return;
  }

  const text = node.getTextContent();

  // Find only 1st occurrence as transform will be re-run anyway for the rest
  // because newly inserted nodes are considered to be dirty
  const emojiMatch = findEmoji(text);
  if (emojiMatch === null) {
    return;
  }

  let targetNode;
  if (emojiMatch.position === 0) {
    // First text chunk within string, splitting into 2 parts
    [targetNode] = node.splitText(
      emojiMatch.position + emojiMatch.shortcode.length,
    );
  } else {
    // In the middle of a string
    [, targetNode] = node.splitText(
      emojiMatch.position,
      emojiMatch.position + emojiMatch.shortcode.length,
    );
  }


  const emojiNode = $createEmojiNode(emojiMatch.unifiedID);
  targetNode.replace(emojiNode);
}


export function registerEmoji(editor: LexicalEditor): () => void {
  // We don't use editor.registerUpdateListener here as alternative approach where we rely
  // on update listener is highly discouraged as it triggers an additional render (the most expensive lifecycle operation).
  return editor.registerNodeTransform(TextNode, textNodeTransform);
}

整合在一起 #

最后，我们通过在编辑器配置中注册 EmojiNode 并执行 registerEmoji(editor) Plugin 启动函数来配置 Lexical 实例。为了简单起见，我们假设 Plugin 采用自己的 CSS 和静态资源分发方式（如果有的话），Lexical 不对此强制任何规则。

请参考 Quick Start (Vanilla JS) 示例 来填补此伪代码中的空白。

import {createEditor} from 'lexical';
import {mergeRegister} from '@lexical/utils';
/* ... */

import {EmojiNode} from './emoji-plugin/EmojiNode';
import {registerEmoji} from './emoji-plugin/EmojiPlugin';

const initialConfig = {
  /* ... */
  // Register our newly created node
  nodes: [EmojiNode, /* ... */],
};

const editor = createEditor(config);

const editorRef = document.getElementById('lexical-editor');
editor.setRootElement(editorRef);

// Registering Plugins
mergeRegister(
  /* ... */
  registerEmoji(editor), // Our plugin
);
