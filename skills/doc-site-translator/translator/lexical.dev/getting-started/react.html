创建基本富文本编辑器 #

为了简化 Lexical 与 React 的集成，我们提供了 @lexical/react 包，它将 Lexical API 封装在 React 组件中，这样编辑器本身以及所有插件都可以使用 JSX 轻松组合。此外，如果需要，您可以延迟加载插件，这样在真正使用它们之前不会付出代价。

首先，安装 lexical 和 @lexical/react：

npm install --save lexical @lexical/react

以下是使用 lexical 和 @lexical/react 的基本富文本编辑器示例。

import {$getRoot, $getSelection} from 'lexical';
import {useEffect} from 'react';

import {AutoFocusPlugin} from '@lexical/react/LexicalAutoFocusPlugin';
import {LexicalComposer} from '@lexical/react/LexicalComposer';
import {RichTextPlugin} from '@lexical/react/LexicalRichTextPlugin';
import {ContentEditable} from '@lexical/react/LexicalContentEditable';
import {HistoryPlugin} from '@lexical/react/LexicalHistoryPlugin';
import {LexicalErrorBoundary} from '@lexical/react/LexicalErrorBoundary';

const theme = {
  // Theme styling goes here
  //...
};

// Catch any errors that occur during Lexical updates and log them
// or throw them as needed. If you don't throw them, Lexical will
// try to recover gracefully without losing user data.
function onError(error) {
  console.error(error);
}

function Editor() {
  const initialConfig = {
    namespace: 'MyEditor',
    theme,
    onError,
  };

  return (
    <LexicalComposer initialConfig={initialConfig}>
      <RichTextPlugin
        contentEditable={
          <ContentEditable
            aria-placeholder={'Enter some text...'}
            placeholder={<div>Enter some text...</div>}
          />
        }
        ErrorBoundary={LexicalErrorBoundary}
      />
      <HistoryPlugin />
      <AutoFocusPlugin />
    </LexicalComposer>
  );
}

添加 UI 控制文本格式 #

Lexical 本身不提供任何类型的 UI，因为它不是一个现成的编辑器，而是一个用于创建自己的编辑器的框架。下面您可以看到上一章集成的示例，现在包含 2 个新插件：

  • ToolbarPlugin - 渲染 UI 控制文本格式
  • TreeViewPlugin - 在编辑器下方渲染调试视图，以便我们可以实时查看其状态

然而，没有 CSS 就无法创建任何 UI，Lexical 也不例外。请注意 ExampleTheme.ts 以及它在此示例中的使用方式，相应的样式定义在 styles.css 中。

💡 完整示例：请访问 StackBlitz 上的 Lexical React Rich 示例 查看完整的可运行示例。

保存 Lexical 状态 #

💡 提示：虽然我们在这里尝试编写自己的插件进行演示，但在实际项目中最好选择 LexicalOnChangePlugin。

现在我们在 React 中有一个简单的编辑器，接下来可能要做的是访问编辑器的内容，例如将其保存到数据库中。我们可以通过更新监听器来实现，该监听器会在每次编辑器状态更改时执行并提供最新状态。在 React 中，我们通常使用插件系统来设置这样的监听器，因为它通过 React Context 为我们提供了对 LexicalEditor 实例的轻松访问。因此，让我们编写自己的插件，在编辑器更新时通知我们。

// When the editor changes, you can get notified via the
// OnChangePlugin!
function MyOnChangePlugin({ onChange }) {
  // Access the editor through the LexicalComposerContext
  const [editor] = useLexicalComposerContext();
  // Wrap our listener in useEffect to handle the teardown and avoid stale references.
  useEffect(() => {
    // most listeners return a teardown function that can be called to clean them up.
    return editor.registerUpdateListener(({editorState}) => {
      // call onChange here to pass the latest state up to the parent.
      onChange(editorState);
    });
  }, [editor, onChange]);
  return null;
}

现在，我们可以在编辑器中实现这一点，并将 EditorState 保存在 React 状态变量中：

function Editor() {
  // ...

  const [editorState, setEditorState] = useState();
  function onChange(editorState) {
    setEditorState(editorState);
  }

  return (
    <LexicalComposer initialConfig={initialConfig}>
      {/*...*/}
      <MyOnChangePlugin onChange={onChange}/>
    </LexicalComposer>
  );
}

好的，现在我们将 EditorState 对象保存在 React 状态变量中，但我们无法将 JavaScript 对象保存到数据库——那么我们如何持久化状态以便稍后加载？我们需要将其序列化为存储格式。为此目的（以及其他目的），Lexical 提供了几种序列化 API，可将 EditorState 转换为可通过网络发送并保存到数据库的字符串。基于我们之前的示例，我们可以这样做：

function onChange(editorState) {
  // Call toJSON on the EditorState object, which produces a serialization safe string
  const editorStateJSON = editorState.toJSON();
  // However, we still have a JavaScript object, so we need to convert it to an actual string with JSON.stringify
  setEditorState(JSON.stringify(editorStateJSON));
}

从那里，连接提交按钮或其他 UI 触发器很容易，它将从 React 状态变量中获取状态并将其发送到服务器以存储在数据库中。

重要提示：Lexical 通常设计为非受控的，因此避免尝试将 EditorState 传递回 Editor.setEditorState 或类似的东西。
