DOMRenderExtension

实验性

DOMRenderExtension 和本页面描述的所有内容都标记为 @experimental，可能在任意两个 Lexical 版本之间发生变化 —— 包括破坏性重命名、签名变更或行为变更 —— 直到 API 稳定为止。我们在 GitHub 仓库 中追踪问题和提案；破坏性变更 将在发布说明中标注。依赖此 扩展的应用应固定其 Lexical 版本，并将升级视为 有意为之的操作。

遗留的基于类的 createDOM / updateDOM / exportDOM 和 默认的 $generateHtmlFromNodes 入口点保持不变，仍然是 不希望追踪实验性 API 的生产应用的 受支持默认方案。

DOMRenderExtension API 在 Lexical v0.44.0 中引入， 并在 v0.45.0 中有重大新增功能

DOMRenderExtension 允许你覆盖 Lexical 节点在协调期间（createDOM / updateDOM / decorateDOM 循环）如何渲染到 DOM，以及它们如何序列化为 HTML 用于剪贴板 导出和 $generateHtmlFromNodes。编辑器内渲染路径 和导出路径都查询同一组覆盖配置，因此单一 声明可以同时影响两者。

反向操作 —— 将 DOM 树转换为 Lexical 节点 —— 请参见 DOMImportExtension。

何时使用​

当变更涉及节点如何转换为 DOM 时，你应该使用 DOMRenderExtension 而不是子类化或 registerMutationListener：

  • 为每个渲染元素添加状态驱动的属性（例如 data-id、data-color）。
  • 在特定节点类型的子节点周围添加额外的包装元素，而无需子类化。
  • 在 HTML 导出期间剥离或重写属性（例如，当 TextNode 不需要时 移除 white-space: pre-wrap 样式）。
  • 自定义 $generateDOMFromRoot 返回的根元素。
  • 根据是剪贴板复制还是完整文档序列化来分支导出行为。

渲染和导出覆盖采用中间件形式 —— 每个覆盖 调用 $next() 获取默认（或更低优先级）结果并 返回自己的结果。这可以在扩展间干净地组合：每个 扩展声明其覆盖而无需与其他扩展协调。

Quick start​

import {
  buildEditorFromExtensions,
  configExtension,
} from '@lexical/extension';
import {DOMRenderExtension, domOverride} from '@lexical/html';
import {defineExtension, isHTMLElement, TextNode} from 'lexical';

const editor = buildEditorFromExtensions(
  defineExtension({
    name: 'app',
    dependencies: [
      configExtension(DOMRenderExtension, {
        overrides: [
          domOverride([TextNode], {
            $createDOM(node, $next, editor) {
              const dom = $next();
              dom.setAttribute('data-fluid', 'true');
              return dom;
            },
          }),
        ],
      }),
    ],
  }),
);

上面的覆盖为每个渲染的 TextNode 添加了 data-fluid="true" 属性。它与 DOMRenderExtension 为 TextNode 配置的其他行为组合 —— 无论是在编辑器内还是 HTML 导出期间。

提示

同一覆盖会在编辑器就地协调 (createDOM/updateDOM/decorateDOM) 和 HTML 导出 ($exportDOM) 时触发。当覆盖仅用于渲染或仅用于导出时， 只需实现相应的方法即可。

覆盖​

覆盖是通过 domOverride 构建的 DOMRenderMatch<T>。它 针对一组节点类（或 '*'）并提供以下中间件方法的任意子集：

覆盖调用时机替换/包装
$createDOM协调器为节点创建 DOMnode.createDOM
$updateDOM协调器更新现有 DOM 节点node.updateDOM
$decorateDOM创建或更新后，子节点协调完成后（累加式 —— 无默认值可替换）
$getDOMSlot协调器询问 ElementNode 的"子节点附加在哪里"ElementNode.getDOMSlot
$exportDOM为剪贴板或 $generateHtmlFromNodes 构建 HTMLnode.exportDOM
$shouldExclude决定是否从 HTML 中排除节点ElementNode.excludeFromCopy
$shouldInclude决定是否在 HTML 中包含节点，通常基于选区默认 selection ? node.isSelected(selection) : true
$extractWithChild因某个子节点被选中而包含该节点，即使它本不应被包含node.extractWithChild

除了 $decorateDOM 外，其他都是 $next() 风格的中间件。调用 $next() 返回默认（或更低优先级覆盖）值；你可以 原样使用、转换它或替换它。

警告

$decorateDOM 是例外：它没有 $next 参数。所有 适用的 $decorateDOM 函数都会无条件调用，且 顺序等效于隐式 $next 调用优先 —— 低 优先级处理器在高优先级之前运行。用于就地 DOM 微调（设置属性、应用状态驱动样式），这些地方 你总是想在其他已完成的基础上叠加。

domOverride 还接受可选的第三个 options 参数，仅在 特定条件下安装覆盖 —— 参见 条件覆盖。

匹配节点​

domOverride 接受 '*'（匹配所有节点）或 NodeMatch<T> 数组 —— 每个条目可以是节点 Klass（例如 TextNode、ParagraphNode）或 $isNodeGuard 断言。

// Apply to all nodes
domOverride('*', { $decorateDOM(node, _, dom) { /* … */ } });

// Apply to TextNode and its subclasses (the Klass form covers subclasses)
domOverride([TextNode], { $createDOM(node, $next) { /* … */ } });

// Apply to a custom guard
domOverride([$isQuoteNode], { $exportDOM(node, $next) { /* … */ } });
提示

使用 Klass 形式比断言 函数开销更小 —— 分发器可以将基于类的匹配编译为 按节点类型键控的直接查找。将 $isNodeGuard 保留给那些 在结构上标识但不共享共同祖先类的节点集合 需要应用相同 DOM 行为的情况。

优先级​

两个覆盖的相对优先级由以下规则确定：

  1. 通配符 ('*') 优先级最高 —— 它们包装所有内容。
  2. 断言（$isParagraphNode）次之。
  3. 子类优先于父类 —— ParagraphNode 的覆盖 在 ElementNode 的覆盖之前运行。
  4. 更接近根的扩展先运行 —— 应用包装 库覆盖。
  5. 依赖关系靠后的扩展先运行 —— 当两个 扩展处于同一层级时，后合并的胜出。
  6. 同一数组中后定义的覆盖 —— configExtension(DOMRenderExtension, {overrides: […]}) 数组的 最后一条先运行。

$next() 沿优先级链向下调用 —— 你的覆盖先运行， 然后是下一个较低优先级的覆盖（或最终是节点的默认实现）。

只读环境编写​

覆盖在协调和导出期间调用，两者都是只读上下文。 不要在覆盖内部调用 editor.update() 或修改节点状态 —— Lexical 正在 为其已有的状态生成 DOM。如果需要对变更做出反应， 请使用节点转换或更新监听器。

Worked examples​

State-driven attribute on every node​

A common pattern: every node carries some app-defined state (e.g. a unique id from NodeState) and you want it surfaced as a DOM attribute in both the editor and the HTML export.

import {createState, $getState, $setState, $getStateChange} from 'lexical';
import {DOMRenderExtension, domOverride} from '@lexical/html';

const idState = createState('id', {
  parse: (v) => (typeof v === 'string' ? v : null),
});

configExtension(DOMRenderExtension, {
  overrides: [
    domOverride('*', {
      $createDOM(node, $next) {
        const dom = $next();
        const id = $getState(node, idState);
        if (id) {
          dom.setAttribute('id', id);
        }
        return dom;
      },
      $updateDOM(nextNode, prevNode, dom, $next) {
        if ($next()) {
          // Lower-priority override requested re-mount; nothing more for us to do
          return true;
        }
        const change = $getStateChange(nextNode, prevNode, idState);
        if (change) {
          const [id] = change;
          if (id) {
            dom.setAttribute('id', id);
          } else {
            dom.removeAttribute('id');
          }
        }
        return false;
      },
    }),
  ],
});

注意 $updateDOM 的形式：它返回 true 告诉协调器 卸载并重新创建 DOM（例如元素标签会改变时），或在执行就地更新后返回 false。调用 $next() 让较低优先级处理器发出重新挂载信号。

Customizing the slot for an ElementNode​

$getDOMSlot controls where child nodes attach in the DOM. The result of $next() is the default ElementDOMSlot returned by ElementNode.getDOMSlot; you can re-derive a new one to insert an extra wrapping element while the root createDOM returns one HTMLElement:

domOverride([SectionNode], {
  $createDOM(node, $next) {
    const root = $next();
    const wrapper = document.createElement('div');
    wrapper.className = 'section-inner';
    root.appendChild(wrapper);
    return root;
  },
  $getDOMSlot(node, dom, $next) {
    // Children go into .section-inner, not directly in the root <section>
    const inner = dom.querySelector('.section-inner');
    return $next().withElement(inner as HTMLElement);
  },
});

调整 HTML 导出​

$exportDOM 返回 DOMExportOutput（{element, after?, append?, $getChildNodes?}）。 覆盖它来剥离不需要的属性或为剪贴板 / $generateHtmlFromNodes 重写输出：

domOverride([TextNode], {
  $exportDOM(_node, $next) {
    const result = $next();
    if (isHTMLElement(result.element)) {
      // Drop white-space: pre-wrap when not needed
      const textContent = result.element.textContent || '';
      if (
        result.element.style.whiteSpace === 'pre-wrap' &&
        !/^\s|\s$|\s\s/.test(textContent)
      ) {
        result.element.style.removeProperty('white-space');
        if (result.element.getAttribute('style')?.trim() === '') {
          result.element.removeAttribute('style');
        }
      }
    }
    return result;
  },
});

选区感知的导出过滤器​

$shouldExclude、$shouldInclude 和 $extractWithChild 共同 控制哪些节点出现在 HTML 输出中，特别是有选区时。 它们按以下优先级顺序运行（从高到低）：

  1. $shouldExclude 返回 true ⇒ 节点被排除（如果是 ElementNode，其子节点可能仍会被提升到其位置）。
  2. $shouldInclude 返回 true ⇒ 包含该节点。
  3. $extractWithChild 对任一子节点返回 true ⇒ 包含该节点，以便被包含的子节点有正确的包装器 （例如，当选中某个 ListItemNode 时包含 ListNode）。
domOverride([CommentMarkNode], {
  // Never include comment marks in exported HTML, but keep their children.
  $shouldExclude: () => true,
});

渲染上下文​

某些覆盖需要知道"这是导出还是编辑器渲染？" 或"这是来自 $generateDOMFromRoot 的根调用吗？"。为此使用 渲染上下文。

createRenderState​

Mint a typed context key with createRenderState:

import {createRenderState} from '@lexical/html';

// True if this serialization is heading to the clipboard (vs. an
// editor reconciliation).
const ClipboardCopyState = createRenderState('clipboardCopy', Boolean);

在覆盖中通过 $getRenderContextValue 读取它：

import {$getRenderContextValue} from '@lexical/html';

domOverride([TableNode], {
  $exportDOM(node, $next, editor) {
    const result = $next();
    if ($getRenderContextValue(ClipboardCopyState, editor)) {
      // Strip editor-only data-* attributes for cleaner clipboard HTML
      // …
    }
    return result;
  },
});

通过 DOMRenderConfig.contextDefaults 为整个渲染调用设置值：

configExtension(DOMRenderExtension, {
  contextDefaults: [
    contextValue(ClipboardCopyState, false),
  ],
  overrides: [/* … */],
})

或通过 $withRenderContext 为单次调用设置：

import {$withRenderContext, contextValue} from '@lexical/html';

const html = $withRenderContext(
  [contextValue(ClipboardCopyState, true)],
  editor,
)(() => $generateHtmlFromNodes(editor, selection));

对于应该持久存在于编辑器上而非限定于单个回调作用域的值， 使用 $setRenderContextValue（或 $updateRenderContextValue 用于更新器）进行命令式设置。 这是 $withRenderContext 的编辑器作用域、持久化对应方案， 它驱动 条件覆盖：更改由 disabledForEditor 断言读取的值 会重新编译渲染配置并重新渲染受影响的节点。

内置渲染状态​

@lexical/html 内置两个渲染状态：

  • RenderContextExport —— 序列化为 HTML 时为 true （$generateDOMFromNodes、$generateDOMFromRoot、 $generateHtmlFromNodes）。用于在编辑器渲染和 HTML 导出之间分支行为。
  • RenderContextRoot —— 仅在最外层 $generateDOMFromRoot 调用期间为 true（即根节点本身 被序列化为 <div role="textbox"> 包装器时）。用于根节点 在完整文档导出中应与作为其他元素子节点时 表现不同的情况。

条件覆盖​

默认情况下，每个覆盖始终安装。向 domOverride 传递可选的第三个 options 参数，仅在特定条件下安装覆盖， 条件完全由 渲染上下文 决定：

domOverride(nodes, config, {
  // Install in the editor's render pipeline (reconciliation + the base for
  // export) only when this returns false. Default: always installed.
  disabledForEditor?: (ctx) => boolean,
  // Participate in a single export/generate session only when this returns
  // false. Default: always participates.
  disabledForSession?: (ctx) => boolean,
});

Each predicate receives a read-only view of the render context (ctx.get(state)) and decides whether the override exists, rather than running on every node and bailing out internally.

disabledForEditor —— 运行时开关​

disabledForEditor 读取持久化编辑器上下文并控制 覆盖是否属于编辑器编译渲染配置的一部分。由于编辑器内 渲染路径使用该配置，这是控制实时协调的作用域。

使用 $setRenderContextValue 切换（参见 渲染上下文）。当写入改变断言结果时， 配置被重新编译，受影响的节点被重新渲染 —— 重新创建 它们的 DOM，因为产生或装饰元素的覆盖只能通过 新的 createDOM 撤销。

import {
  $setRenderContextValue,
  createRenderState,
  domOverride,
  DOMRenderExtension,
} from '@lexical/html';
import {LineBreakNode} from 'lexical';

const LineBreakWrapDisabled = createRenderState(
  'lineBreakWrapDisabled',
  () => false,
);

configExtension(DOMRenderExtension, {
  overrides: [
    domOverride(
      [LineBreakNode],
      {
        $createDOM(node, $next) {
          const wrapper = document.createElement('span');
          wrapper.className = 'visible-non-printing-linebreak';
          wrapper.appendChild($next());
          return wrapper;
        },
        // … $getDOMSlot to expose the inner <br>, $updateDOM to recreate when
        // the wrap state changes …
      },
      {disabledForEditor: (ctx) => ctx.get(LineBreakWrapDisabled)},
    ),
  ],
});

// Later — e.g. from a settings change. The override is removed from the
// pipeline entirely when disabled (no per-node checks remain), and existing
// line breaks re-render without the wrapper.
$setRenderContextValue(LineBreakWrapDisabled, true, editor);

因为覆盖在禁用时完全不在分发链中，所以 没有逐节点开销 —— 这是相对于在钩子内部检查标志的优势。

disabledForSession — per-export gating​

disabledForSession is evaluated once at the start of each export/generate session ($generateHtmlFromNodes, $generateDOMFromNodes, $generateDOMFromRoot) against that session's context. It controls whether the override participates in that walk only, and has no effect on live reconciliation — reconciliation isn't a session, so there's nothing for the predicate to read.

This suits export transforms you only want for certain serializations (e.g. a "terse" copy) without paying for the middleware on every export:

const TerseExport = createRenderState('terseExport', () => false);

configExtension(DOMRenderExtension, {
  overrides: [
    domOverride(
      '*',
      {
        $exportDOM(node, $next) {
          const result = $next();
          // … strip theme classes / unneeded styles …
          return result;
        },
      },
      {disabledForSession: (ctx) => !ctx.get(TerseExport)},
    ),
  ],
});

// A normal export skips the override entirely…
const html = editor.read(() => $generateHtmlFromNodes(editor));

// …while a terse export opts in for that one walk:
const terseHtml = editor.read(() =>
  $withRenderContext([contextValue(TerseExport, true)], editor)(() =>
    $generateHtmlFromNodes(editor),
  ),
);

选择作用域​

你想要...使用
在运行时为整个编辑器开关渲染行为disabledForEditor + $setRenderContextValue
仅在特定序列化中包含导出转换disabledForSession + $withRenderContext
在始终安装的覆盖内分支行为使用 $getRenderContextValue 读取上下文（无需选项）

入口点​

三个顶层辅助函数使用配置的覆盖：

函数用途
$generateDOMFromNodes(container, selection?, editor?)遍历 RootNode.getChildren() 并将每个追加到 container。设置 RenderContextExport=true。
$generateDOMFromRoot(container, root?)类似上面但包含根节点本身（默认包装在 <div role="textbox"> 中）。设置 RenderContextExport=true 和 RenderContextRoot=true。
$generateHtmlFromNodes(editor, selection?)便捷方法：创建 <div>，调用 $generateDOMFromNodes，返回其 innerHTML。

三者都是只读的（在 editor.read() 内使用或配合你自己的 editor.update()）。

功能​

当前：

  • 按节点类或全局覆盖 createDOM、updateDOM、decorateDOM、getDOMSlot、 exportDOM、shouldExclude、shouldInclude、extractWithChild。
  • 中间件 $next() 链可跨扩展组合。
  • 类型化渲染上下文（createRenderState、RenderContextExport、 RenderContextRoot）允许覆盖根据调用模式分支。
  • 单一声明同时应用于编辑器内协调和 HTML 导出。
  • 通过 disabledForEditor / disabledForSession 条件安装， 使用命令式 $setRenderContextValue / $updateRenderContextValue 在运行时开关编辑器作用域覆盖。

未来：

  • 每个节点类上的遗留 node.createDOM / node.updateDOM / node.exportDOM 继续并行工作；此迭代中没有任何内容改变默认行为。扩展选择加入覆盖管道，结果覆盖替换匹配节点的基于类默认值。
