# 模板：failure-analysis

## 填充说明

| 占位符 | 填充者 | 填充源 | 时机 |
|--------|--------|--------|------|
| `{n}` | 主循环 | tasks.md 任务 ID | run_failure_analysis 时 |
| `{attempt}` | 主循环 | task.attempt（外层计数） | 阻断分析时 |
| `{round}` | 主循环 | 1（attempt==3）或 2（attempt==6） | 阻断分析时 |
| `{3 或 6}` | 主循环 | 由 `{round}` 推导：round=1 -> 3，round=2 -> 6 | 阻断分析时 |
| `{内层历史}` | 主循环 | 内层 quality_round 评分趋势 + 收敛建议 + 根因分布 | 阻断分析时 |
| `{问题台账摘要}` | 主循环 | issue-log.md 摘要（未闭合的阻断/重要级） | 阻断分析时 |
| `{历史 reports 路径列表，逐轮摘要}` | 主循环 | task.failure_history | 阻断分析时 |

> **渲染说明**：主循环 `render` 函数替换占位符后，将下方模板正文发送给 failure analyzer。analyzer 逐维度判断阻断性，按 round 分支输出结论。本版本在原 6 维度基础上扩展，新增「根因标签熔断」维度。

# 阻断性分析：T{n}（第 {round} 轮，attempt {attempt}）

## 分析对象
- 触发条件：第 {3 或 6} 轮检查未通过（外层 attempt 达阻断分析门槛）
- 任务预期：读取 tasks.md 中 T{n}（预期产出 + 完成标准）
- 最近一轮 review：路径 `run_dir/inner/T{n}/r{attempt}-q{last_q}-review.md`
- 内层质量轮历史：{内层历史}（q_round=1..N 的评分与收敛建议趋势）
- 问题台账摘要：{问题台账摘要}（未闭合的阻断/重要级）
- 已尝试方案：{历史 reports 路径列表，逐轮摘要}

## 分析维度（逐条判断，含判定样例）

### 1. 缺失依赖
是否缺少前置条件/外部资源/其他任务产出？
- 🔴 阻断样例：T3 依赖 T1 的 API 定义，T1 已 blocked -> T3 阻断
- 🟢 非阻断样例：T2 依赖外部 npm 包未安装，可 `npm install` 解决 -> 非阻断

### 2. 技术不可行
当前技术栈/约束下是否无法实现？
- 🔴 阻断样例：要求 IE8 兼容 ES6 模块，技术不可行
- 🟢 非阻断样例：性能未达目标但可通过优化逼近 -> 非阻断

### 3. 需求矛盾
完成标准是否自相矛盾或与目标冲突？
- 🔴 阻断样例：完成标准要求同时"零依赖"和"使用 lodash"
- 🟢 非阻断样例：命名规范冲突，可统一约定 -> 非阻断

### 4. 反复失败同因
连续多轮（外层 attempt 或内层 quality_round）失败是否同一根因未解决？
- 🔴 阻断样例：3 轮都因同一类型错误失败，根因未解决
- 🟢 非阻断样例：3 轮失败原因不同，逐步逼近正确 -> 非阻断

### 5. 验证合理性
完成标准是否可验证？验证命令是否合理？
- 🔴 阻断样例：完成标准为"用户体验好"，无命令可证明 -> 阻断
- 🟢 非阻断样例：验证命令需调整（缺参数），修正后可验证 -> 非阻断

### 6. 路由错误
任务是否被路由到错误技术域 agent？
- 🔴 阻断样例：前端任务被路由到后端 agent，反复产出不匹配
- 🟢 非阻断样例：路由偏差但 self 可降级处理 -> 非阻断

### 7. 根因标签熔断（v3 新增）
基于 issue-log.md 检查同根因问题是否在多轮中复发：
- 复用 issue-log 中已闭合条目 vs 未闭合条目的根因分布
- **熔断触发条件**：同一根因标签问题在 ≥ 2 个 quality_round 中独立出现且未被根治
- 🔴 阻断样例：「测试覆盖不足」根因连续 3 个 quality_round 出现，无论如何补丁都未根治 -> 熔断升级
- 🟢 非阻断样例：第 1 轮出现，第 2 轮已通过模型级修复（消维度/改派生/并机制）解决 -> 非阻断

### 8. 内层耗尽（v3 新增）
- 内层 quality_round 是否已用尽（达 N 轮仍未收敛）？
- 🔴 阻断样例：3 个 quality_round 评分始终 < 6，无任何提升迹象
- 🟢 非阻断样例：评分稳步提升（6.5 -> 7.5 -> 8.0），刚达收敛门槛 -> 非阻断

## 判定（按 round 分支）

- **round=1（attempt==3）**：
  - 阻断性 / 无法实现：上述任一为 🔴 且无法绕过 -> blocked，升级询问
  - 非阻断性：全部为 🟢 或可修正 -> 第 2 阶段重试
- **round=2（attempt==6，已达上限）**：无论阻断与否 -> blocked，升级询问（不再重试）

## 输出
- 结论：🔴 阻断性 / 🟢 非阻断性
- 理由：{依据上述维度，指明命中的维度与样例}
- 建议：{升级询问的选项 / 重试的修正方向}
- **若触发根因熔断**：明确指出根因标签 + 历史 issue-log 条目 + 应转向的模型级修复方向
