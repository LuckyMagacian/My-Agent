# 结果检查：T{n} 第 {m} 轮

## 检查对象
- 任务预期：读取 tasks.md 中 T{n}（预期产出 + 完成标准）
- executor 产出摘要：{附}
- VCS diff：执行 `git diff` 获取
- 验证命令：IDENTIFY 阶段确定

## 检查 Gate（五步，必须执行）
1. **IDENTIFY**：哪些命令能证明完成标准满足？（测试命令/lint/类型检查/构建/运行）
2. **RUN**：完整执行验证命令（不跳过、不缩短）
3. **READ**：查看完整输出 + 退出码 + 失败数
4. **VERIFY**：输出是否支撑完成声明？（对照完成标准逐条）
5. **声明**：仅在本轮验证证据支撑时才声明通过

## 声明-证据对照表

| 完成声明类型 | 必需证据 | 判定标准 |
|------------|---------|---------|
| 测试通过 | 测试命令输出 + 退出码 | 退出码 0 且通过数>0 |
| Lint 通过 | lint 命令输出 + 退出码 | 退出码 0，无 error |
| 构建成功 | 构建命令输出 + 产物路径 | 退出码 0 且产物文件存在 |
| Bug 修复 | Red-Green 证据（见下方） | 修复前失败 + 修复后通过 |
| 文档更新 | git diff | 显示新增/修改段落 |
| Agent 委派产出 | target agent 执行摘要 + VCS diff | 摘要与 diff 一致 |

## 危险词清单

以下词汇出现在 executor 自述时，视为**未提供证据**，不得据此声明通过：
- 英文：should / probably / seems / Done / Great / works / fixed
- 中文：应该 / 大概 / 可能 / 完成 / 搞定 / 没问题 / 差不多

## 修复类任务 Red-Green Gate

对 bug 修复类任务，必须执行 Red-Green 验证：
1. **IDENTIFY**：原症状复现命令（修复前必须能复现失败）
2. **RUN RED**：执行复现命令，验证修复前确实失败（红灯）
3. **APPLY FIX**：确认 executor 已应用修复
4. **RUN GREEN**：执行复现命令，验证修复后通过（绿灯）
5. **声明**：红灯->绿灯均成立才声明通过

## 核心原则
- **不信任 executor 自述**：必须独立验证，不接受"应该可以"/"大概完成"
- **证据优先**：通过/未通过必须有命令输出或 diff 支撑

## 输出（写入 reports/T{n}-r{m}.md）
- 结论：✅ 通过 / ❌ 未通过
- 证据：{验证命令输出摘要 + diff 摘要}
- 原因（未通过时）：{具体问题，逐条}
- 建议（未通过时）：{修正方向，可执行}
