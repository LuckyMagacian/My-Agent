## 填充说明

| 占位符 | 填充者 | 填充源 | 时机 |
|--------|--------|--------|------|
| `{n}` | 主循环 | tasks.md 任务 ID | dispatch_reviewer 时 |
| `{attempt}` | 主循环 | task.attempt（外层计数） | dispatch_reviewer 时 |
| `{q_round}` | 主循环 | task.quality_round（内层计数） | dispatch_reviewer 时 |
| `{附}` | 主循环 | executor 5 段交付物路径 + 摘要 | dispatch_reviewer 时 |
| `{整合意见}` | 主循环 | 上轮 arbiter 整合意见（如有） | dispatch_reviewer 时 |

# 评估任务：T{n}（外层 attempt {attempt}, 内层 q{q_round}）

## 检查对象
- 任务预期：读取 tasks.md 中 T{n}（预期产出 + 完成标准）
- executor 5 段交付物：{附}（标题/正文/变更说明/摘要/未落实项声明）
- VCS diff：执行 `git diff` 获取
- 整合意见（如有）：{整合意见}
- 减法轮约束（如宣布）：{减法轮约束}
- 上轮评分：{prev_score}（停滞检测用）

## 评估视角（默认单视角：通用质量评估）

主循环默认单视角，按以下三维度评分（总分 10）：
- 正确性：5 分（满足任务目标与约束；逻辑/数据/引用是否正确）
- 完整性：3 分（任务要求部分是否齐全；边界/异常/必要说明是否补全）
- 一致性：2 分（内部自洽 1 分 + 与上游对齐 1 分，无上游时与上游对齐子项自动满分）

> 如任务分发方注入了多视角集合，按注入视角分别评估并各产一份报告。

## 评估 Gate（5 步 + 防膨胀审视）

### Step 1: IDENTIFY（5 步 Gate，必须执行）
- 哪些命令能证明完成标准满足？（测试/lint/类型检查/构建/运行）
- 修复类任务：识别原症状复现命令（修复前必须能复现失败）

### Step 2: RUN
- 完整执行验证命令（不跳过、不缩短）
- 修复类任务：RUN RED（修复前必须能复现失败）→ 确认 executor 已应用修复 → RUN GREEN（修复后必须通过）

### Step 3: READ
- 查看完整输出 + 退出码 + 失败数，不遗漏失败信息

### Step 4: VERIFY
- 逐条对照完成标准，输出是否支撑完成声明
- 阻断 vs 重要 vs 建议级问题分类（按 SKILL.md §10.1）

### Step 5: 声明-证据对照
- 测试通过 → 测试命令输出 + 退出码（0 且通过数>0）
- Lint 通过 → lint 输出 + 退出码（0，无 error）
- 构建成功 → 构建输出 + 产物路径（0 且产物存在）
- Bug 修复 → Red-Green 证据
- 文档更新 → git diff（显示新增/修改段落）
- Agent 委派 → target agent 摘要 + VCS diff（一致）

> 危险词：should/probably/seems/Done/Great + 应该/大概/可能/完成/搞定/差不多 → 视为未提供证据，不构成通过理由

## 防膨胀审视义务（每个 reviewer 必须承担）

### A. 零增量审计
对 executor 变更说明中标注「新增项（行为定义项）」的每一条：
- 复核「删除该条款后是否损失行为定义？」的论证
- 判定论证成立：是 / 否 + 理由
- 不成立者：列为「重要」级问题（含位置+不成立理由+建议删除或保留）
- 减法轮内的新增（即使有论证）：直接拒绝，列为阻断级

### B. 简洁性审视
清点交付物中**可删除而行为定义无损**的条款/段落/分支：
- 逐条列为「重要」级问题（含位置+可删论证）
- 归属完整性维度（按 SKILL.md §10.3）
- 删除不因此对完整性评分产生负向影响（删除的是冗余，不属于任务指令要求部分）

### C. 根因标签标注
对每个问题标注根因标签（粒度判据：可用同一类修复方向消除的一组问题）：
- 例：API 设计错误 / 测试覆盖不足 / 错误处理缺失 / 文档不准确 / 命名不一致 / 抽象不当 / 性能瓶颈
- 优先复用 issue-log.md 既有标签；确无适配时新建
- 同根因问题跨 quality_round 第 2 次出现 → 触发熔断，标签是关键

## 评分

按三维度独立评分（默认视角）：

| 维度 | 分值 | 评分 |
|------|------|------|
| 正确性 | 5 | X/5 |
| 完整性 | 3 | X/3 |
| 一致性 | 2 | X/2 |
| **总评** | **10** | **X/10** |

> 评分需在 Step 4 VERIFY 证据基础上给出；无证据支撑的高分视为不合格。

## 收敛建议

- **默认判定规则**：当且仅当 **评分 ≥ 阈值（默认 8）** 且 **阻断级问题 = 0** 时给出「建议收敛」；否则「不建议收敛」+ 列明未满足条件
- 输出：「建议收敛 / 不建议收敛」+ 依据摘要（引用具体评分维度与阻断/重要问题数）

## 问题清单

逐条列出，每条含：
- **ID**（自动生成：T{n}-R{attempt}Q{q_round}-{seq}）
- **严重级别**：阻断 / 重要 / 建议
- **位置**：交付物中的章节号或行
- **证据**：原文摘录（最小要素：位置 + 摘录）
- **期望标准**：期望达到的状态
- **修改方向**：可执行的修改指引
- **根因标签**：复用或新建
- **归属维度**：正确性 / 完整性 / 一致性 / 简洁性

## 无问题维度确认

已检查但未发现问题的维度显式标注「通过」。

## 输出（写入 run_dir/inner/T{n}/r{attempt}-q{q_round}-review.md）
- 评分（X/10）+ 维度分解
- 收敛建议 + 依据
- 问题清单（按级别分段）
- 零增量审计结果
- 简洁性审视结果
- 无问题维度确认
- ⚠️ 不得自述"完成"——收敛由 arbiter（主循环）按 SKILL.md §6 核验

## 附：评分锚点参考
- 9-10：可交付，几乎无瑕疵
- 7-8：可用但有 1-2 个重要问题需修正（< 8 不建议收敛）
- 5-6：核心问题未解决，需大改
- 3-4：基础正确性被破坏
- 1-2：交付物不可用
